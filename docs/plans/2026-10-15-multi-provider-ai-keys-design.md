# 多平台模型密钥

> 日期：2026-10-15
> 状态：**已确认设计，未实施**
> 范围：密钥页 `packageAi/keys`、`family_ai_keys`、`ai.act` 调模型。不改管家编排、不改查库。

## 1. 问题

管家只把密钥当成 DeepSeek。`baseUrl` 和模型在页面上不出现，服务端默认写成 DeepSeek。DeepSeek 返回 503 或正文中断时，没有另一家可换，对话停在「助手暂时不可用」。

密钥表已有 `provider`、`baseUrl`、`model`。调用时默认密钥优先，失败后再试一把，最多两把。缺的是可选的平台和模型，以及按平台填写的地址。

## 2. 目标与非目标

**目标**

- 用户选平台后直接贴 API key。该平台的默认模型已选好，地址由预设写入。
- 需要时可以改成该平台下的另一个预设模型。名称仍可选。
- 默认密钥失败（超时、429、5xx）时，自动试下一把，下一把可以是另一家平台。
- 已保存的 DeepSeek 密钥不用迁移。

**非目标**

- 用户自填接口地址或模型 id。
- 豆包。它的模型 id 是账号里的接入点，没法写进预设。
- 推理模型。管家要的是一份 JSON 计划。
- 同一次请求试完家里全部密钥。上限仍是两把。
- 在成功回复里说明换过平台。

## 3. 用户操作

密钥页在现有输入框上方增加平台选择。选中平台后，模型停在该平台的默认项，用户不用再点一次。

平常路径：选平台 → 粘贴 API key → 保存。名称留空时，用平台名当标签。

改模型是可选项，只列出该平台目录里的模型。列表除名称和掩码外，显示平台和模型，能看出默认的是哪一家。家里最多仍是 3 把。

## 4. 预设目录

目录在服务端，是 `baseUrl` 和模型 id 的唯一来源。每个平台有一个默认模型。模型 id 以实现时各家文档为准，加减模型只改目录，不改表。

| 平台 | 默认模型 | 地址 |
|---|---|---|
| DeepSeek | `deepseek-chat` | `https://api.deepseek.com/v1` |
| Kimi | `kimi-k2.6` | `https://api.moonshot.cn/v1` |
| 智谱 | `glm-4.7-flash`（另有 `glm-4.5-flash`） | `https://open.bigmodel.cn/api/paas/v4` |
| 通义千问 | `qwen-plus`（另有 `qwen-turbo`） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 阶跃星辰 | `step-3.5-flash` | `https://api.stepfun.com/v1` |
| MiniMax | `MiniMax-M2` | `https://api.minimaxi.com/v1` |

保存时只接受目录中的平台和模型。请求里自带的 `baseUrl` 丢掉，避免指向任意内网地址。`response_format: json_object` 是否附带，写在该模型的预设上。这家不支持就不带。返回 400 时不换下一把密钥，所以不兼容的参数要在预设里关掉。

调用使用库存的完整前缀，不再自动补 `/v1`。智谱的路径是 `/api/paas/v4`，补 `/v1` 会指错。

## 5. 失败时

顺序不变：默认密钥优先，其余按添加时间，最多两把。超时、连接失败、429、5xx 换下一把。

| 情况 | 用户看到 |
|---|---|
| 下一把成功 | 正常结果，不说明换过平台 |
| 两把都失败 | 「助手暂时不可用，请稍后重试」，并可以去密钥页 |
| 密钥无效且没有下一把 | 提示去密钥页检查，不展示上游英文原文 |
| 额度用尽 | 现有的余额文案 |

## 6. 验收

- 只选平台并贴 key，保存后的地址和模型等于该平台默认预设。
- 自填的 `baseUrl` 不会入库。
- 默认密钥读超时或 503 后，会用另一平台的第二把再请求一次。
- 已有 DeepSeek 密钥仍能调用。
- 智谱预设的请求路径不包含多余的 `/v1`。
