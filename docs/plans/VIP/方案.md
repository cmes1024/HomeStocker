## 1. 背景与目标

### 1.1 为什么要做会员

1. **摊平可变成本**：AI V1/V2 每次调用都会产生模型 API 费用（DeepSeek 约 ¥1/百万 tokens），按量付费必须有对应的收入覆盖。
2. **摊平固定成本**：云开发套餐（数据库读 / 写 / 存储 / 云函数调用）、小程序认证、后续研发人力。
3. **验证付费意愿**：家庭协同台账是强需求，但 AI 管家是强付费意愿锚点，先跑通转化漏斗再决定是否追加功能。

### 1.2 非目标（本阶段不做）

- ❌ 个人会员（与家庭成员关系耦合复杂，且付费决策人通常是家庭户主）
- ❌ 次卡 / 点数包（模型复杂度高，转化率通常不如订阅）
- ❌ 分销、返利、多级代理（合规风险 + 实现成本）
- ❌ 角色权限（免费版也是全员同权，会员版只扩容量不拆权限）
- ❌ iOS / Android 差异化价格（先统一价，后续根据渠道数据再调）

## 2. 套餐与权益分层

### 2.1 三层权益矩阵

| 权益维度 | 免费版 | 家庭会员（推荐） | 高级会员 |
|---------|--------|------------------|----------|
| **定价** | 0 元 | ¥12/月 · ¥98/年（省 ¥46） | ¥25/月 · ¥198/年 |
| **核心定位** | 能把台账用起来 | 全家 AI 提效 + 深度体验 | 重度用户 + 数据安全感 |
| 家庭数量 | 1 个 | 3 个 | 不限 |
| 单家庭成员上限 | 5 人 | 12 人 | 不限 |
| 物资总数上限 | 50 件 | 不限 | 不限 |
| 空间总数上限 | 3 个 | 不限 | 不限 |
| 标签总数上限 | 20 个 | 不限 | 不限 |
| 过期提醒订阅（每人） | 10 条物资 / 人 | 不限 | 不限 |
| 命名主题 | 5 套默认 | 17 套全解锁 | 全解锁 + 自定义封面图上传 |
| 家庭消息历史留存 | 最近 30 天 | 全部 | 全部 + 支持导出 Excel / CSV |
| **AI V1 拍照录入（`ai.extract`）** | 5 次 / 人 / 天（体验额度） | **不限次数** + 优先走更准模型 | 不限次数 + 最高精度模型 |
| **AI V2 自然语言助手（`ai.act`）** | 新用户前 7 天赠送 20 轮体验，之后关闭 | 30 轮 / 家庭 / 天 | 100 轮 / 家庭 / 天 + 优先响应 |
| AI 调用上下文窗口 | 基础（只带家庭树） | 扩展（带最近 20 条活动日志） | 最大（带近 30 天消息 + 常用物资模式） |
| **BYOK（自带密钥）** | ✅ 可用（不占免费额度） | ✅ 可用（可与官方额度切换） | ✅ 可用 + 支持多 provider |
| 专属客服 / 反馈通道 | 公开社区 | 邮件 48h 内响应 | 微信专属群 + 工单优先处理 |

### 2.2 设计说明

1. **免费版阈值**：50 件物资 / 3 个空间刚好够单身 / 小两口「尝鲜」；想认真用就必须升级，避免大量僵尸家庭占着数据库。
2. **AI V1 体验额度按人不按家**：避免 5 人家庭靠人数把免费次数堆到 25 次/天。
3. **AI V2 只给会员 + 新用户小量赠送**：这是最强付费钩子，不能在免费版敞开用；7 天 20 轮足够让用户建立依赖。
4. **高级会员存在意义**：拉高声望用户 LTV，同时给预算敏感用户一个「家庭会员就够用」的锚点。

## 3. 订阅单位与归属判定

### 3.1 为什么按「家庭」卖，不按「人」卖

1. **产品本质是家庭协同**：付费决策人是家庭户主（创建者或默认第一成员），一个人付费全家受益，感知价值远高于「只有我自己能用」。
2. **数据模型天然契合**：`families.ownerOpenid` 直接就是付费人；`memberships` 自然描述谁能共享权益。
3. **避免重复购买校验**：按家庭卖，一个 `familyId` 同时只能有一个生效订阅，逻辑简单、并发安全、对账清晰。

### 3.2 付费人与使用人分离的处理

- **购买入口只对户主可见**：非户主进入会员页时，顶部提示「请联系家庭创建者为家庭开通会员」，并展示创建者昵称 + 一键复制邀请话术。
- **转让户主 = 转让订阅**：如果后续做了户主转让能力，订阅归属跟着 `families.ownerOpenid` 走（无需改 `subscriptions` 表，只看 `_id = familyId`）。
- **成员离开 / 加入**：只要订阅还在，新加入的成员立刻享受会员权益；离开的成员在新家庭里按新家庭套餐走。

### 3.3 多家庭切换时的权益判定

- 用户有多个 `memberships` 时，每个 `familyId` 独立判定自己的套餐；
- 切换家庭后，前端立刻从 `getMyFamily` 里拿到新家庭的 `subscription` 字段并刷新 UI；
- 云函数端永远用「当前请求对应的 `currentFamilyId`」查 `subscriptions`，不受用户端切换影响。

## 4. 门控（Gatekeeper）实现

### 4.1 总体思路

> 前端只做展示与跳转引导；**真实拦截必须在云函数层**。所有会产生成本或受套餐限制的云函数 action，进入业务逻辑前统一调 `checkEntitlement`。

### 4.2 统一工具模块

新增 `cloudfunctions/_shared/gatekeeper.ts`（或同目录 `.js`，视项目语言情况），导出：

```typescript
interface CheckOptions {
  familyId: string;
  openid: string;
  feature:
    | 'familyCount'       // 创建 / 加入新家庭
    | 'memberCount'       // 邀请成员加入
    | 'itemCount'         // 新建物资
    | 'spaceCount'        // 新建空间
    | 'tagCount'          // 新建标签
    | 'expireSubsCount'   // 订阅某物资过期提醒
    | 'themes'            // 使用非默认主题
    | 'messageHistory'    // 查询超过 30 天前的消息
    | 'export'            // 导出数据
    | 'aiCapture'         // ai.extract 拍照录入 V1
    | 'aiAssist';         // ai.act 自然语言助手 V2
  consume?: boolean;          // true = 实际扣减额度（默认 false 只探）
  byokAvailable?: boolean;    // 该家庭是否有可用 BYOK Key（ai 相关 feature 用）
}

interface CheckResult {
  allowed: boolean;
  reason?:
    | 'plan_locked'         // 该套餐不包含此功能
    | 'quota_exceeded'      // 本期额度已用完
    | 'subscription_expired'// 订阅已过期
    | 'fair_use_daily'      // 单日公平使用上限
    | 'cost_circuit_breaker'; // 成本熔断
  remaining?: number;           // 剩余额度（前端展示用）
  upgradeHint?: string;         // 用户可读引导文案
  quotaTotal?: number;
  quotaPeriod?: 'day' | 'month' | 'forever';
}

export declare function checkEntitlement(opts: CheckOptions): Promise<CheckResult>;
```

### 4.3 接入点清单（只改入口，不改业务）

| 云函数 | Action | 接入 Feature | 说明 |
|-------|--------|--------------|------|
| `family` | `create` / `join` | `familyCount` | 创建或加入新家庭前检查当前 openid 已有 membership 数量 |
| `family` | 邀请（新增 action 或在 join 里） | `memberCount` | 被邀请者接受前检查当前家庭 `memberCount` 是否已达上限 |
| `item` | `create` | `itemCount` | 创建物资前计数 |
| `space` | `create` | `spaceCount` | |
| `tag` | `create` | `tagCount` | |
| `item` | 订阅（在 create / update 里） | `expireSubsCount` | 写 `itemExpireSubs` 前先查该 openid 在本家庭已有订阅条数 |
| `family` | `updateBackground` | `themes` | 非默认 themeId 要拦截 |
| `activity` | `list`（当传了早于 30 天的 cursor） | `messageHistory` | 免费版查历史消息时截断 |
| （新增）`export` | 任意 | `export` | 高级会员功能 |
| `ai` | `extract` | `aiCapture` | **成本关键点，必须接**；若 `byokAvailable = true`，跳过额度直接放行 |
| `ai` | `act` | `aiAssist` | **同上**，新用户 7 天体验额外判断 `users.createdAt` |

### 4.4 各 feature 的额度 / 套餐规则（给 checkEntitlement 内部查表）

```typescript
const FEATURE_MATRIX: Record<CheckOptions['feature'], {
  free:    { planAllowed: boolean; reset: 'day'|'month'|'forever'; limit: number };
  family:  { planAllowed: boolean; reset: 'day'|'month'|'forever'; limit: number };
  premium: { planAllowed: boolean; reset: 'day'|'month'|'forever'; limit: number };
}> = {
  familyCount:      { free: { ..., forever: 1 },        family: { forever: 3 }, premium: { forever: Infinity } },
  memberCount:      { free: { forever: 5 },             family: { forever: 12 },premium: { forever: Infinity } },
  itemCount:        { free: { forever: 50 },            family: { forever: Infinity }, premium: { ... } },
  spaceCount:       { free: { forever: 3 },             family: { forever: Infinity }, premium: { ... } },
  tagCount:         { free: { forever: 20 },            family: { forever: Infinity }, premium: { ... } },
  expireSubsCount:  { free: { forever: 10 },            family: { forever: Infinity }, premium: { ... } },
  themes:           { free: { planAllowed: false },     family: { planAllowed: true }, premium: { planAllowed: true } },
  messageHistory:   { free: { forever: 30 /* 天 */ },   family: { forever: Infinity }, premium: { ... } },
  export:           { free: { planAllowed: false },     family: { planAllowed: false }, premium: { planAllowed: true } },
  aiCapture:        { free: { day: 5 },                 family: { day: Infinity }, premium: { ... } },
  aiAssist:         { free: { planAllowed: false /* 体验期例外单独判断 */ }, family: { day: 30 }, premium: { day: 100 } },
};
```

### 4.5 成本熔断（硬保险，无视套餐）

在 `checkEntitlement` 里对 **`aiCapture` 和 `aiAssist`** 额外做两道硬闸：

1. **单家庭日调用总次数**：任何套餐单日合计不得超过 200 次（公平使用，防止脚本刷）。
2. **单家庭月累计模型成本**：在 `usageLogs.modelCost` 汇总超过 ¥50（5000 分）时，自动强制切到 BYOK 或提示升级。

> 这两条规则写死在代码里，不进数据库 `aiCapabilities`，避免被运营误改。

## 5. BYOK（家庭自带密钥）与官方额度的关系

### 5.1 优先级

```
该请求是否可走 BYOK？
 ├─ 是（有 familyAiKeys 且 provider/model 匹配）
 │   └─ 直接放行，不扣官方额度，也不触发套餐判断
 └─ 否 → 进入 checkEntitlement 判断套餐 / 额度
```

### 5.2 免费用户的 AI 路径

免费用户想用 AI V1/V2：

1. **自带 Key** → 直接用，不限次数，用户自己承担 API 费用。
2. **不带 Key** → 走官方额度，免费 V1 5 次/天 / 人；V2 必须开通会员。

这样官方额度只覆盖「不想折腾 Key、愿意付费」的用户，模型成本可控。

## 6. 支付接入方案

### 6.1 两条路径对比

| 维度 | 方案 A：微信小程序虚拟支付（`wx.requestMidasPayment`） | 方案 B：微信支付 JSAPI（小程序支付） |
|------|------------------------------------------------------|-------------------------------------|
| 官方定位 | 用于虚拟道具、订阅等数字商品 | 用于实物或服务类商品 |
| 苹果抽成 | iOS 走 IAP 抽成 30% | 规避（但小程序审核有被卡风险） |
| 开通门槛 | 需要申请「虚拟支付」类目，腾讯侧审核 | 需要有小程序支付商户号（认证费 ¥300 / 年） |
| 回款周期 | T+7 到小程序余额，可提现 | T+1 到商户号 |
| 退款 | 平台有标准接口 | 自行对接 |

### 6.2 推荐节奏

1. **起步（< 1000 付费用户）**：先用 **方案 A 虚拟支付** 跑通，快速验证转化。
2. **扩大（> 1000 付费 / iOS 抽成明显）**：升级到 **方案 B**，套餐描述改为「家庭物资管理咨询服务」而非「AI 次数」，规避虚拟支付类目限制。
3. 两条路径共享同一张 `orders` 与 `subscriptions` 表，只在 `orders.source` 区分。

### 6.3 支付状态机（订单）

```
pending ──► paid ──► refunded
  │
  └──► expired（24h未支付自动关闭）
```

- `paid` 成功回调 → 调 `extendSubscription(familyId, plan, period)` 延长订阅；
- `refunded` 回调 → 不回退订阅（防滥用），但人工后台可手动处理。

### 6.4 自动续费

- 起步阶段 **不做自动续费**（小程序虚拟支付自动续费需要单独申请 + 用户接受度低）。
- 手动在 `expireNotify` 同一个定时触发器里加：**到期前 7 天 / 3 天 / 1 天** 给户主发订阅消息，引导去会员页续费。

## 8. 免费体验与防刷

### 8.1 新用户 AI V2 体验

- 体验资格：`users.createdAt` 在 7 天内 且 该 openid 历史上没有过任何 `orders.paid` 记录；
- 体验额度：累计 20 轮 `ai.act`（按 openid 计，不随家庭变）；
- 用完或过期：立刻落 `plan_locked`，跳会员页。

### 8.2 防止「用多开小号刷免费额度」

因为免费版 `itemCount` 是按家庭计、`aiCapture` 是按 openid 计，已经天然扛住大部分刷量。再补两条：

1. 同一个微信号（openid 不变）建多个家庭：`familyCount` 免费版上限 1，建不了第二家。
2. 新注册用户在首次调用 `ai.extract` 之前必须先完成至少 1 次手动 `item.create`（过滤掉纯来刷 AI 的注册机）。

## 9. 数据监控与关键指标

所有指标通过 `usageLogs` + `orders` + `subscriptions` 三表每日聚合，跑一个新云函数 `billing.dailyReport` 输出：

| 指标 | 公式 | 健康参考值 |
|------|------|-----------|
| DAU / 家庭数 | 当日有任意活动的家庭数 | 基准线 |
| AI 调用总次数 | `usageLogs where feature in (aiCapture, aiAssist) count` | 与 DAU 比例 > 0.3 说明 AI 被用起来 |
| 免费→付费转化率 | 「30 天内用过 AI V1/V2 且不是会员的家庭」中 30 天内新下单付费的占比 | > 5% 及格，> 10% 优秀 |
| 会员续费率 | 30 天前到期的付费家庭中，到期后 14 天内续费的比例 | 月卡 > 60%，年卡 > 80% |
| ARPU（单付费家庭月均收入） | 滚动 30 天 `orders.amount` 之和 / 付费家庭数 | ¥8~¥12（对应 ¥12/月定价，考虑年卡折扣） |
| 单活跃家庭月模型成本 | 滚动 30 天 `usageLogs.modelCost` 之和 / 活跃家庭数 | 目标 < ¥1，红线 ¥3 |
| 毛利润率 | (ARPU × 付费占比 − 单家庭模型成本 − 云开发单家庭摊销) / ARPU × 付费占比 | > 70% 健康，< 30% 必须提价或降模型精度 |

## 10. 安全规则（与 `database-rules.json` 对齐）

新增的三张集合 **客户端读写一律 deny**：

- `subscriptions`：只能由 `billing` / `family` 云函数读 / 写；读路径可经由 `getMyFamily` 把订阅快照返回给客户端。
- `orders`：只能由 `billing` 云函数写；户主可只读自己的下单历史（`openid == auth.openid`）。
- `usageLogs`：只能由 `gatekeeper` 写（append only）；**任何客户端不得读**（避免暴露模型成本等内部信息）。
