# 家庭会员增值方案 — 数据模型

> 目录：[`README.md`](./README.md) · [`方案.md`](./方案.md) · [`落地步骤.md`](./落地步骤.md)  
> 对齐风格：`miniprogram/cloud/collections.md`

本文档定义会员机制引入后 **新增的 3 个集合**、**现有集合的字段扩展**，以及对应的 **索引 / 安全规则 / 换环境步骤**。

---

## 1. 新增集合总览

| 集合名 | 作用 | 归属维度 | 客户端写权限 |
|--------|------|----------|-------------|
| `subscriptions` | 每个家庭当前生效的套餐与到期时间（**订阅真相**） | 家庭 | ❌ deny（仅 `billing` / `family` 云函数写） |
| `orders` | 支付订单流水，对账与审计用 | 家庭 + 个人 | ❌ deny（仅 `billing` 云函数写；户主可读自己的历史） |
| `usageLogs` | 每次受门控功能调用的记录，含实际模型成本（**成本真相**） | 家庭 + 个人 | ❌ deny（仅 `gatekeeper` 里 append；客户端不读） |

> 说明：**不**引入「月度额度」独立集合。为了简单，月度 / 每日额度直接通过聚合 `usageLogs` 按时间段 `count` 或 `sum(cost)` 得出；若 QPS 高再引入 `monthlyUsages` / `dailyUsages` 做近实时聚合表。

---

## 2. 集合字段详解

### 2.1 `subscriptions`

一家一单，`_id` 直接用 `familyId`，读写最高效。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `_id` | string | ✅ | 恒等于 `familyId`（主键，天然唯一） |
| `familyId` | string | ✅ | 与 `_id` 相同，便于按前缀查询（冗余，留着防止解散清理逻辑漏写） |
| `plan` | string | ✅ | `'free'` \| `'family'` \| `'premium'`。默认 `'free'`。 |
| `status` | string | ✅ | `'active'` \| `'expired'` \| `'cancelled'`。新建 `'active'`；到期前不变；到期后定时任务改 `'expired'`。`'cancelled'` 保留给未来人工处理。 |
| `startAt` | number | ✅ | 本期开始时间（ms 时间戳）。免费版 = 家庭创建时间。 |
| `endAt` | number | ✅ | 本期到期时间（ms 时间戳）。免费版 = `Infinity` 的替代值 `9007199254740991`（Number.MAX_SAFE_INTEGER），避免判断 null。 |
| `autoRenew` | boolean | ✅ | 是否自动续费。起步阶段一律 `false`，后续接自动续费再用。 |
| `trialUsed` | boolean | ✅ | 是否已经使用过新用户 7 天 AI V2 体验（按 openid 判不在此，这里留占位，后续可做家庭赠送） |
| `source` | string | ✅ | `'default'`（建家免费） \| `'purchase'` \| `'trial'` \| `'promo'` \| `'gift'`。 |
| `lastOrderId` | string | ❌ | 最近一次续费或开通的 `orders._id`，方便跳转对账。 |
| `createdBy` | string | ❌ | 最初付费人 openid。免费版为家庭创建者 openid。 |
| `createdAt` | number | ✅ | |
| `updatedAt` | number | ✅ | 每次 `endAt` 变化或套餐切换都更新。 |

**初始写入时机**：`family.create` / `family.join` 成功后，如果对应 `familyId` 在 `subscriptions` 里不存在，则 `upsert` 一条 `plan: 'free'` 的记录（幂等）。

**降级逻辑**：`endAt` 过期后仍读不到就兜底为 free，不要因为缺 doc 就整个家庭挂掉。

---

### 2.2 `orders`

纯流水 append-only，永不改旧记录（只更新 `payStatus` / `payAt` / `transactionId`）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `_id` | string | ✅ | 自动生成。不要用时间戳拼接，避免同一 ms 并发冲突。 |
| `familyId` | string | ✅ | 为哪个家庭买的（结算单位）。 |
| `openid` | string | ✅ | 支付人 openid。 |
| `plan` | string | ✅ | `'family'` \| `'premium'`。 |
| `period` | string | ✅ | `'month'` \| `'year'`。 |
| `amount` | number | ✅ | 实付金额，单位 **分**。起步价：family 月 1200 / 年 9800，premium 月 2500 / 年 19800。 |
| `currency` | string | ✅ | 恒为 `'CNY'`。 |
| `payStatus` | string | ✅ | `'pending'`（创建订单，待支付） \| `'paid'`（支付成功回调已确认） \| `'refunded'`（人工退款） \| `'expired'`（24h 未支付关闭）。 |
| `payAt` | number | ❌ | 实际支付时间戳。`payStatus = 'paid'` 时必填。 |
| `transactionId` | string | ❌ | 微信支付 / 虚拟支付侧的流水号，对账用。 |
| `paymentSource` | string | ✅ | `'wx-virtual'`（起步方案 A） \| `'wx-jsapi'`（后续方案 B） \| `'promo-code'`（兑换码） \| `'manual'`（后台补偿）。 |
| `promoCode` | string | ❌ | 若使用了优惠码，记录之。 |
| `discountAmount` | number | ❌ | 优惠减免金额（分）。原价与实付之差 = 优惠。 |
| `extendDays` | number | ✅ | 本单延长的天数（月卡 = 30，年卡 = 365，优惠券 = 实际赠送天数）。支付成功后用这个字段去延长 `subscriptions.endAt`。 |
| `note` | string | ❌ | 运营备注。 |
| `createdAt` | number | ✅ | 订单创建时间。 |

**索引需求**：见 §3。

---

### 2.3 `usageLogs`

**成本与额度真相源**。每一次受门控的调用都 append 一条，不允许更新或删除。按 `createdAt` 做 TTL（可选），比如 180 天后自动归档到冷存储。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `_id` | string | ✅ | 自动生成。 |
| `familyId` | string | ✅ | 结算维度单位。 |
| `openid` | string | ✅ | 实际使用者。 |
| `feature` | string | ✅ | `'familyCount'` \| `'memberCount'` \| `'itemCount'` \| `'spaceCount'` \| `'tagCount'` \| `'expireSubsCount'` \| `'themes'` \| `'messageHistory'` \| `'export'` \| `'aiCapture'` \| `'aiAssist'`。 |
| `result` | string | ✅ | `'allowed'` \| `'denied_plan'` \| `'denied_quota'` \| `'denied_expired'` \| `'denied_fairuse'` \| `'denied_circuit_breaker'`。**拒绝也要写日志**，用来观察拦截率和反作弊。 |
| `cost` | number | ✅ | 本 feature 消耗了多少「单位」。大多数 feature 是 1；ai 按 tokens 折算也可以先写 1 后面再细化。 |
| `quotaBefore` | number | ❌ | 扣减前剩余额度（调试与对账方便）。 |
| `quotaAfter` | number | ❌ | 扣减后剩余额度。 |
| `modelCostFen` | number | ❌ | 底层模型 / 云函数实际产生的成本，单位 **分**（可小数，如 0.05 分）。只在 aiCapture / aiAssist 这类有真实开销的 feature 填。**此字段客户端永不可见。** |
| `provider` | string | ❌ | 模型调用时的真实 provider：`'official-deepseek'`（官方 Key） \| `'byok-deepseek'`（用户自带 Key，此时 modelCostFen = 0） \| `'none'`。 |
| `denyReason` | string | ❌ | 当 result = denied* 时，附详细原因。 |
| `requestId` | string | ❌ | 云函数请求 ID，排障时串联日志。 |
| `createdAt` | number | ✅ | 调用时间（ms）。 |

## 3. 索引（控制台手工创建）

与 `collections.md` 风格一致，逐条在微信云开发控制台 → 数据库 → 集合 → 索引 里添加。

### 3.1 `subscriptions` 索引

`_id` 主键无需手建。

| 建议名称 | 属性 | 字段（按顺序） | 用途 |
|----------|------|----------------|------|
| `status_endAt` | 非唯一 | `status` 升序，`endAt` 升序 | 定时任务「每天扫一遍 status='active' 且 endAt < 今天 + 3 天」发续费提醒 / 改 expired |
| `plan_status` | 非唯一 | `plan` 升序，`status` 升序 | 运营报表：各套餐当前订阅数 |

### 3.2 `orders` 索引

| 建议名称 | 属性 | 字段（按顺序） | 用途 |
|----------|------|----------------|------|
| `familyId_createdAt` | 非唯一 | `familyId` 升序，`createdAt` **降序** | 某家庭的购买历史（倒序看最近一单） |
| `openid_createdAt` | 非唯一 | `openid` 升序，`createdAt` **降序** | 某个人的购买历史 |
| `payStatus_createdAt` | 非唯一 | `payStatus` 升序，`createdAt` 升序 | 扫 pending 超时单 / 每日营收报表 |
| `transactionId` | **唯一** | `transactionId` 升序 | 微信侧回调幂等：已处理过的单号直接跳过，防止重复延长订阅 |
| `paymentSource_payStatus` | 非唯一 | `paymentSource`，`payStatus` | 分渠道对账 |

### 3.3 `usageLogs` 索引

量会很大（每个 AI 调用都一条），索引要精简。

| 建议名称 | 属性 | 字段（按顺序） | 用途 |
|----------|------|----------------|------|
| `familyId_createdAt` | 非唯一 | `familyId` 升序，`createdAt` **降序** | 查询某家庭最近的使用记录（限前 N 条） |
| `openid_createdAt` | 非唯一 | `openid` 升序，`createdAt` **降序** | 查询某人最近的使用记录 |
| `family_feature_day` | 非唯一 | `familyId`，`feature`，`createdAt` 范围 | `checkEntitlement` 算今日 / 本月额度时用：按家庭 + feature + 时间范围 count。实际只要 `familyId_createdAt` 前缀 + 代码里过滤 feature 就行，不必再建复合索引 |
| `createdAt` | 非唯一 | `createdAt` 降序 | 月度成本报表按时间扫 |

> 优化建议：如果实时聚合 `usageLogs` 按天 count 太慢（比如 AI 调用量 > 1w/天），再引入一张 `dailyUsages` 汇总表，`_id = \`${familyId}_${feature}_${YYYYMMDD}\``，每次扣减前 `inc count`。起步阶段先不用。

## 4. 现有集合字段扩展

### 4.1 `users` — 不改

AI V2 7 天体验资格按 `users.createdAt` + `usageLogs` 里该 openid 的 `aiAssist` 累计条数判，无需在 `users` 表加列。

`users` 表仍保持：

```
_id · _openid · currentFamilyId · nickname · updatedAt
```

### 4.2 `families` — 不改

户主判断仍用 `families.ownerOpenid`。会员归属直接读 `subscriptions._id = families._id`，不用在 `families` 里加冗余字段。

## 5. 安全规则（追加到 `database-rules.json`）

原则：**客户端一律 deny 写**；读权限严格控制。

```json
{
  "subscriptions": {
    ".read": false,
    ".write": false
  },
  "orders": {
    ".read": "auth.openid == resource.data.openid",
    ".write": false
  },
  "usageLogs": {
    ".read": false,
    ".write": false
  }
}
```

**读路径说明**：

- `subscriptions`：客户端 **不直读**。通过 `family.getMyFamily` 把快照（`plan` / `endAt` / 剩余额度）塞进返回值；会员详情页走 `billing.getSubscription` 云函数拿完整信息。
- `orders`：客户端允许读 **自己 openid 下的历史订单**（户主查自己给自己家买过的单）；运营侧查全部订单走云函数 + 管理员白名单（暂不需要）。
- `usageLogs`：**任何客户端都不读**。成本 / 额度信息在云函数内聚合后通过 `billing.getUsage` 返回给合法成员。

## 6. 换环境部署步骤

新环境或迁移时，按本节顺序执行。对应 `miniprogram/cloud/collections.md` §「换环境部署」。

### 6.1 建集合（与现有集合并列）

`subscriptions` · `orders` · `usageLogs`

### 6.2 贴安全规则（§5）

### 6.3 建索引（按 §3 逐条）

顺序：先建 `orders.transactionId` 唯一索引（支付回调幂等最重要），再建 `subscriptions.status_endAt`（到期任务），其余视报表需求可上线后补。

### 6.4 上传 / 更新云函数

```
family        // create / join 里 upsert subscription 免费记录；解散清理 subscriptions / orders
billing       // 新增；createOrder / wechatCallback / getSubscription / getUsage / applyPromo
ai            // extract / act 开头调 checkEntitlement
item          // create 开头调 checkEntitlement(itemCount) + expireSubsCount
space         // create 开头调 checkEntitlement(spaceCount)
tag           // create 开头调 checkEntitlement(tagCount)
expireNotify  // 同一定时触发器里追加 续费提醒发送 逻辑
```

### 6.5 跑一遍脚本补齐历史数据

上线当天对所有存量家庭做：

```
for family in families:
  if subscriptions.doc(family._id) not exists:
    subscriptions.add({ _id: family._id, familyId: family._id, plan: 'free', status: 'active',
                        startAt: family.createdAt, endAt: MAX_SAFE_INTEGER, autoRenew: false,
                        trialUsed: false, source: 'default', createdAt: now, updatedAt: now })
```

## 7. `getMyFamily` 返回订阅快照的字段建议

在 `family.getMyFamily` 的返回对象里追加字段（命名一致，方便前端挂 `globalData`）：

```typescript
interface FamilyWithSubscription extends Family {
  subscription: {
    plan: 'free' | 'family' | 'premium';
    status: 'active' | 'expired' | 'cancelled';
    endAt: number;
    // 下面几项给前端展示「剩余额度」用，不用再单独 call 一次
    quotas: {
      aiCapture: { used: number; limit: number; period: 'day' };   // 免费版 5/天，会员 Infinity
      aiAssist:  { used: number; limit: number; period: 'day' };   // 家庭版 30/天，高级 100/天
    };
    // 户主信息：用来决定能不能点购买按钮
    isOwner: boolean;    // auth.openid === families.ownerOpenid
    ownerOpenid: string;
    ownerNickname: string;
  };
}
```

这样任意页面 `app.globalData.family.subscription` 都能读到，不需要额外请求。
