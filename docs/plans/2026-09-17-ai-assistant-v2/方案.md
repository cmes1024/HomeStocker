# AI 助手 V2 — 技术方案

> 目录：[`README.md`](./README.md)  
> 讨论：[讨论过程.md](./讨论过程.md)  
> 状态：**实施中**；OpenSpec change `ai-assistant-v2` 正在落地

## 1. 目标

在不影响现有手动台账和 AI V1 拍照向导的前提下，增加一条 **自然语言** 助手：

1. 每次先拿到家庭结构树（空间 / 位置 / 标签）。
2. 把 **系统能力边界** 和当次状态交给模型，由模型决定调用哪些已开放接口。
3. 执行器按白名单调用现有 `item` / `space` 云函数；模型不直接写库。
4. 结束后用代码生成操作汇报（含「可能重复」，不自动合并）。

成功标准：家人打一句话，能查库存/临期、新开物资、改已有字段、在确认后删除；回到清单能看到同一套数据。不要求语音、看图、半屏聊天、LangGraph。

## 2. 和 V1 的区分

| | AI V1（拍照录入） | AI 助手 V2（本文） |
|--|-------------------|-------------------|
| 分包 | `packageAi` | **新分包**（建议 `packageAiAssist`） |
| 输入 | 图 + 行内文字（语音本拟用 STT） | **仅文本** |
| Prompt | `aiPrompts.item-extract-v1` | `aiPrompts.assist-act-v2`（新文档） |
| 模型产出 | 按行草稿卡片 | **调用计划**（`ask` / `calls`） |
| 结构上下文 | extract 时现场 join 目录 | **家庭树** 集合，结构变更时同步 |
| 能力范围 | 只服务入账抽取 | 查 / 记 / 改 / 删（以能力表为准） |
| 入口 | 清单 AI 浮窗 → 采集页 | 新入口；**不改** V1 浮窗现有行为（OpenSpec 再定是否并列） |

09-07 半屏对话 + 独立 FastAPI/LangGraph：**不是 V2**。V2 脑子留在云函数一次（或「探查后再一次」）计划里。

## 3. 耦合边界

```
清单 / 详情 / 编辑 / packageAi     ← 不改主路径行为
        │
        │  仅被调用
        ▼
  item / space / tag 现有 action
        ▲
        │
packageAiAssist ──► 云函数 ai（新 action）
                      ├─ 读 familyTrees + aiCapabilities + assist-act-v2
                      ├─ 代发 DeepSeek（复用 familyAiKeys）
                      └─ 执行器调 item / space
```

### 3.1 允许改动（实施时由 OpenSpec 收紧白名单）

| 位置 | 改什么 |
|------|--------|
| `app.json` | 注册新分包 |
| 清单 / 家庭 | **只加入口**（navigateTo），不改拉数、筛选、编辑 |
| `cloudfunctions/ai/` | 新 action：读树、读能力、act、能力/树的确保与重建 |
| `cloudfunctions/space` `tag` | 结构写成功后旁路更新家庭树 |
| `cloudfunctions/family` | 建家种子树；解散删树 |
| `cloud/database-rules.json` `collections.md` | 新集合 |
| 本目录文档 | 同步 |

### 3.2 禁止

- 改 `pages/items/edit`、详情、V1 采集页的业务逻辑来「顺便接助手」
- 在 `ai` 里复制一套 `createItem` 校验
- 把物资列表嵌进 `families` 或家庭树
- 复活 `pages/chat` 当 V2 主 UI
- 客户端直写新集合；提示词 / 能力表 / 密钥不下发到端上明文
- 本版接语音、视觉、流式、LangGraph

无密钥：与 V1 相同，引导去现有 `packageAi/keys`（或家庭页额度入口），不新做一套 BYOK。

## 4. 用户动线

```
新分包输入一句话
        │
        ▼
云函数 ai.act（标准 agent 循环，见 openspec/changes/ai-assist-agent-runtime/）
  读能力表（enabled）+ 家庭树 + focus/history
  [详情进来则带 focus 物资]
        │
        ▼
模型 → 计划（模型是唯一意图路由器；无关键词预路由）
  ask[] 非空 → 页面槽位卡 / 确认卡，零写入
  probe     → 最多探一次物资，必要时再问模型一轮（忽略第二次 probe）
  reply 且无 calls → 直接答复（结构问答只依据 TREE；库存须已有 FOCUS/PROBE/工具结果）
  calls[]   → tool registry 按序执行白名单（含临期订阅面板 tool）
        │
        ▼
代码拼操作汇报（已记录 / 已修改 / 失败 / 可能重复）或 subscribe 面板
```

追问：芯片作为下一句发回，并带上最近对话上下文重跑 act。连续两轮仍缺槽位 → 落到现有编辑表（预填已解析字段）。页面是对话列表，发送后清空输入；不复活 `pages/chat`。

删除：能力表 `confirm: true`，无确认不执行；确认后重放绑定 id，跳过模型。

> 实现演进：早期 `act.js` 曾用意图正则短路结构/盘点/订阅；**已删除**。现行控制流见 change `ai-assist-agent-runtime`（`agent/orchestrator.js` + `tools/`）。

## 5. 架构

```
小程序 packageAiAssist（文本、追问、汇报 / 订阅面板）
        │
        ▼
ai.act（OPENID + currentFamilyId + membership）
  ├─ agent/context：ensure 能力表 / act prompt、家庭树、focus/history
  ├─ agent/model：填 prompt → DeepSeek JSON 计划
  ├─ agent/guardrails：confirm 重放、硬 deny、库存权威（无臆造盘点）
  └─ tools/registry：enabled ∩ ¬hardDeny，顺序执行 itemService / locationWrite
        │
        ▼
item.search / listExpiring / create / update / remove / merge
space.createLocation
item.expireSubscribePanel（→ status: subscribe）
```

身份只信 `OPENID`。请求里的 `familyId` 忽略。超时与 V1 extract 同级（控制台 60s，HTTP ~45s），整段返回、不流式。

模块布局与规格：`openspec/changes/ai-assist-agent-runtime/`。**不再**使用意图预路由（结构-only / 盘点强制 probe / 订阅入口短路等已移除）。

## 6. 家庭树

独立集合，建议名 `familyTrees`，`_id = familyId`。

| 字段 | 说明 |
|------|------|
| `familyId` | 与 `_id` 相同 |
| `rev` | 单调版本，和结构写入对齐 |
| `spaces` | `{ id, name, isDefault, locations: [{ id, name }] }[]` |
| `tags` | `{ id, name }[]` |
| `updatedAt` | |

**不含**物资、数量、日期、消息、成员。

喂给模型时只渲染名称（空间 → 缩进位置、标签列表）。id 留给执行器把「厨房/冰箱」收成 `spaceId`/`locationId`。

### 6.1 更新

在这些 **写成功之后** 旁路更新（失败不回滚正写；下次 act 发现 stale 则重绘）：

- `space` 增删改、位置增删改
- `tag` 增删改、默认标签种子
- 建家时 `ensureDefault` / 种子标签之后写一棵空货树
- 执行器 `createLocation` 成功后

**不**在 `item` 增删改时更新。

### 6.2 重绘

`ai.act`（或显式 rebuild）若文档缺失、解析失败、或 `rev` 与结构水位不一致：从 `spaces` + `locations` + `tags` 现场拼一棵并写回。对用户仍是同一次助手调用。

解散家庭：删 `familyTrees` 文档，与 keys / media 同类清理。

## 7. 系统能力表

独立集合，建议名 `aiCapabilities`，固定 `_id` = `assist-act-v2`。应用级，不是按家庭。

| 字段 | 说明 |
|------|------|
| `version` | 数字；云函数种子更高则覆盖 |
| `apis` | 能力数组 |
| `updatedAt` | |

每条 `apis[]`：

| 字段 | 说明 |
|------|------|
| `id` | 计划里的 `use`，如 `item.search` |
| `fn` / `action` | 云函数名与 action |
| `enabled` | false 则不进 prompt、执行器拒绝 |
| `confirm` | true 则必须先经过用户确认（或计划里带已确认标记） |
| `args` / `hint` | 给模型看的参数说明 |

### 7.1 V2 种子（enabled）

- `item.search`
- `item.listExpiring`
- `item.create`
- `item.update`
- `item.remove`（`confirm: true`）
- `space.createLocation`

### 7.2 占位（enabled: false，不进 prompt）

- `item.merge`
- `space.create` / `update` / `remove`（房间）
- `tag.create` / `update` / `remove`
- 一切 `family.*`、密钥、`ai.extract` / `transcribe`

### 7.3 硬底线

代码内死表：即使库里把 `family.leave` 标成 enabled 也不可执行。能力表迭代的是产品范围，不是唯一安全闸。

### 7.4 迭代

加能力：云函数先有 action → 种子 `enabled: true` 且 `version + 1` → 必要时加 act prompt 分节（prompt 自己的 version 可分开加）。关能力：`enabled: false` + version。部署后下次 `act` 自动灌新表。

渲染 `{{CAPABILITIES}}` 与执行器校验 **读同一份**。

## 8. Prompt

`aiPrompts` 新文档 `_id` = `assist-act-v2`，`version` 从 1 起。与 `item-extract-v1` 并列，互不覆盖。

占位符：`{{TODAY}}` `{{WEEKDAY}}` `{{FAMILY_NAME}}` `{{CAPABILITIES}}` `{{TREE}}` `{{FOCUS}}` `{{PROBE}}`。

正文按接口 **分节**（查 / 新开 / 改 / 删 / 补位置），同一次调用全部可见。不要先由代码选用其中一节。

模型只输出一个 JSON 计划，不要 Markdown。建议形状：

```
{
  "ask": [],
  "probe": null,
  "calls": [
    { "use": "item.create", "name": "牛奶", "quantity": 2, "unit": "瓶", "spaceName": "厨房", "locationName": "冰箱" }
  ]
}
```

规则要点（细节进 OpenSpec / 提示词草稿）：

- `ask` 非空则 `calls` 不执行。
- `use` 必须是本轮 `{{CAPABILITIES}}` 里的 `id`。
- 空间/位置/标签用树里的原名；树里没有的位置可走 `space.createLocation`（若该能力开启）。
- 物资用短号或「空间/位置 + 名称」；短号只能引用 `FOCUS` / `PROBE` 里出现过的。禁止输出数据库 `_id`。
- 没说合并：新开用 `item.create`，不要把已有同名改数量。
- 相对日期按 `{{TODAY}}` 换成 `YYYY-MM-DD`。

`probe`：模型认为必须看某位置上的物资时填写 `{ spaceName, locationName, name? }`。执行器最多探一次，把命中行填进 `{{PROBE}}` 再问一轮；本轮已有 PROBE 则忽略再次 probe，避免循环。

## 9. 执行器

1. 校验 `use` ∈ enabled ∩ 硬底线。  
2. 名称 → id（对照本轮树；位置缺失且计划要求则 `createLocation`）。  
3. `confirm` 类能力：页面未确认则改写成 `ask`，不调用。  
4. 按 `calls` 顺序调用；失败停下，已成功的保留，汇报写明。  
5. `item.create` / `update` / `remove` 的 `source` 为 `agent`。  
6. 不在 `ai` 内复制领域校验。

详情页带 `focus`：探查可省；模型仍可对这件 `update`/`remove`，或忽略 focus 去 `create`。

## 10. 探查与汇报

探查用现有 `item.search` 或 `familyId + locationId` 过滤，只回紧凑行（短号、名、量、单位、空间位置、日期）。不把全家物资塞进 prompt。

操作汇报 **代码模板**，不调模型。建议块：已执行的调用、失败、可能重复（同空间同位置名称可对上、且本轮有新开）。可能重复只展示，**不调用合并**。

## 11. 分包与密钥

新分包只含助手页（输入、追问芯片、汇报）。模型与语音 SDK 不进清单主包。

密钥复用 `familyAiKeys` 与 `packageAi/keys`。V2 不新增 provider；仍云函数 axios 出网。

## 12. 非目标（V2 方案范围外）

- 语音转文字、拍照视觉、清单出图  
- 半屏聊天 UI、流式 SSE、仓库 `agent/` 接真库  
- 自动合并；合并语义  
- 助手内建房间、改标签、切家庭、角色权限  
- Elasticsearch / RAG  
- 把 V1 采集改造成 V2（可长期并存）

## 13. 下一步

实施以 `openspec/changes/ai-assistant-v2/` 为准。**不要**改 V1 `item-extract-v1` 行为来迁就 V2。
