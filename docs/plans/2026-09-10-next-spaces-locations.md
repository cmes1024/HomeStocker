# HomeStocker 下一版重点：家庭空间与存放位置

> 日期：2026-09-10  
> 状态：已讨论确认（侧聊收敛）  
> 定位：**MVP 台账闭环之后的下一版开发重点**  
> 前置：`docs/plans/2026-09-10-mvp-cloudbase-redesign.md`（协同台账）已落地；多家庭与全站主题背景已具备

---

## 1. 产品原则

| 原则 | 说明 |
|------|------|
| **清单为主** | 全家物资列表 + 增删改仍是默认日常路径 |
| **空间为辅** | 空间/位置是浏览与归类模式，不另造第二套库存 |
| **先记账后整理** | 无空间时自动落在默认「仓库」，编辑时可改 |
| **用户登记空间** | 房间/区域由家庭成员自己创建，不强制官方房间目录 |
| **低成本氛围** | 空间页用产品提供的**默认氛围图**（可模糊）作背景，首版不做实景上传、不做 3D/看房编辑器 |

**明确不做（本版）：** 用户实景多图拼接与箭头漫游、Three.js 家庭建模、ECharts 空间图、按官方「玄关/客厅…」固定房间包、icon 自由拼贴编辑器（可作为更后可选模式）。

---

## 2. 信息架构

```
家庭
 └─ 楼层（可选；小平层可隐藏）
      └─ 空间（用户创建；默认「仓库」）
           └─ 位置（可选，用户自定义，如「右边第一个柜子」）
                └─ 物资
```

- **空间**：语义上的房间/区域（厨房、地下室杂物间、仓库…）。  
- **位置**：某空间下的细粒度存放点；添加时可空。  
- **楼层**：大宅分组用；模型预留，UI 默认可不露；也可用空间命名暂代（如「2F 主卧」）推迟实体楼层。

### 导航（建议）

1. 家庭页（或物资页）一个入口模块：**逛空间** / **家庭空间**  
2. → **空间列表页**（当前家庭下用户登记的空间；可按楼层折叠）  
3. → **单空间页**：默认氛围图作轻微模糊背景 + 该空间下物资清单；每条展示所属**具体位置**（有则显示）  
4. 物资首页仍为**全家清单**，可增加按空间筛选（本版可做可缓）

## 3. 录入与默认规则

### 添加物资

| 字段 | 规则 |
|------|------|
| 名称 / 数量 / 备注 | 与现网一致 |
| 空间 | 若家庭下尚无任何空间 → **懒创建并选用默认空间「仓库」**；若已有空间 → 下拉选择（默认可仍指向仓库或上次选择） |
| 具体位置 | 可选；下拉「本空间已有位置」+「新建位置」 |

### 编辑物资

- 可改所属空间、具体位置（从仓库挪到厨房柜等）。

### 默认空间「仓库」

- 系统保证每个家庭至少能落到一个空间；**仅在「还没有任何空间」时自动创建**。  
- 允许改名；删除需约束（迁出物资或禁止删光最后一个空间），避免家里无空间可挂。

---

## 4. 单空间页体验（氛围）

- 背景：产品侧**一张（或少数）默认室内氛围图**，全空间共用即可；略模糊，突出前景清单。  
- 内容：该 `spaceId` 下物资列表；行内或副文案展示位置名（如「右边第一个柜子」）。  
- 点位气泡叠图：本版**非必须**；有清单 + 位置文案即可。拥挤时仍以清单为准。  
- 与全站「家庭主题背景」关系：进入空间页可用空间氛围图覆盖/替换；退出恢复家庭主题。

## 5. 数据模型（草案）

在现有 `users` / `families` / `memberships` / `items` 上扩展，**禁止**把空间树嵌进 `families` 大数组。

### `spaces`

| 字段 | 说明 |
|------|------|
| `familyId` | 归属家庭 |
| `name` | 如「仓库」「厨房」 |
| `floorId` | 可选 |
| `isDefault` | 是否默认仓库 |
| `coverKey` | 可选，默认图配置 key |
| `createdAt` / `updatedAt` | |

### `locations`（具体位置）

| 字段 | 说明 |
|------|------|
| `familyId` | |
| `spaceId` | 所属空间 |
| `name` | 如「右边第一个柜子」 |
| `createdAt` / `updatedAt` | |

### `floors`（可二期）

| 字段 | 说明 |
|------|------|
| `familyId` | |
| `name` | 如「1F」「2F」 |
| `sort` | |

### `items` 增量

| 字段 | 说明 |
|------|------|
| `spaceId` | 必填（创建时保证有默认仓库） |
| `locationId` | 可空 |

索引建议：`spaces.familyId`；`locations.spaceId`；`items.familyId+spaceId`；`items.locationId`。

### 云函数

- 扩展 `item` create/update：写入/校验 `spaceId`、`locationId`（属当前家庭）。  
- 新增或并入 `space`（或 `family` 下 action）：空间 CRUD、位置 CRUD、确保默认「仓库」。  
- 页面与未来 Agent **同一写入口**；`items.source` 规则不变。

## 6. 页面与任务切片（实施顺序）

1. **模型与云函数**：`spaces` / `locations`、默认仓库、`item` 带空间字段  
2. **编辑/新增物资**：空间选择 + 可选位置；无空间时静默仓库  
3. **空间列表 + 单空间页**：默认氛围底图 + 清单与位置文案  
4. **家庭页入口模块**：进入空间列表  
5. **（可选）** 全家清单按空间筛选；楼层实体与分组  

---

## 7. 更后可选（非本版重点）

- 预设 icon 积木拼布局（仍是同一 `spaces/locations` 的另一种 UI）  
- 单张实景图 + 热点  
- 多图箭头「看房」式编排  
- 真正 3D / Three.js 建模  

原则：空间能力先服务「东西在哪」；漫游编辑器验证需求后再做。

---

## 8. 成功标准（下一版可体验）

1. 新家庭首次添加物资，无需先建空间，自动落在「仓库」  
2. 可创建自定义空间，编辑物资时可改所属空间与具体位置  
3. 从家庭入口进入空间列表，再进入某空间，看到该空间物资及位置文案  
4. 全家物资清单路径仍可用；数据不双写、不分裂
