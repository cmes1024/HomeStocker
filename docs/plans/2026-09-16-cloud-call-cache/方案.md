# 云函数读缓存方案

> 目录：`docs/plans/2026-09-16-cloud-call-cache/`  
> 场景清单：[`场景.md`](./场景.md)（S 号以那份为准）  
> 状态：已落地（调用层；页面未改）。行为合同：`openspec/specs/cloud-read-cache/spec.md`。  
> 约束：**业务页面零改**；缓存只活在云函数调用层

## 1. 目标

减少小程序对云开发**函数调用次数**的消耗。页面继续 `onShow` 里拉数、继续 `callItem('search')` 这类写法；第二次同样的读在调用层直接返回，不打到云。

不把「要不要刷新」写进各个 Page。不引入 `wx.storage`、实时监听、首页 bootstrap 大接口、客户端直读 `activities`。

## 2. 耦合边界

```
页面 / db.js                    禁止改：不调 invalidate、不判断命中、不探水位
        │
        ▼
  utils/cloud.js                唯一入口：读缓存 / 写后作废 / 回前台探水位
        │
  utils/queryCache.js           内存表 + 同 key 并发合并
        │
        ▼
  wx.cloud.callFunction         未命中才出去
```

业务代码看起来仍在请求。省的是**出网次数**，不是 `await` 本身。

### 允许改动的文件（白名单）

| 文件 | 改什么 |
|------|--------|
| `miniprogram/utils/queryCache.js` | **新建**。内存缓存、key、并发 inflight |
| `miniprogram/utils/cloud.js` | 读走缓存、写成功按策略作废、回前台时探 cursor |
| `miniprogram/utils/session.js` | `getMyFamily` 改为 `callFamily`，禁止自己 `callFunction` |
| `miniprogram/app.js` | `onHide` / `onShow` 只打「是否从后台回来」旗标，不拉业务数据 |
| `miniprogram/cloudfunctions/activity/index.js` | 新增 `action: 'cursor'` |
| 本目录文档 | 同步 |

`db.js` 已全部经 `callItem` / `callSpace`，**不必改**。各 Page、组件、`theme.js`、`route.js` **不在白名单**。

新增云函数 action 时：只改 `cloud.js` 里的策略表，仍不改页面。

### 明确不在本波

- 改任何页面的 `onShow` / `load` / loading 文案（标签页命中后仍可能快闪 `loading`，本波接受）
- onboarding 里 `setAppFamily(null)`（S101，冷启动 `globalData` 本就是空的；暖启动再单开）
- 持久化、离线队列、冲突合并
- 家人改空间名/标签名/主题的实时可见（S902～S904）
- 物资写成功但活动插入失败时的水位漏洞（S906，接受）

## 3. 行为（三层）

```
自己增删改 ──► 写成功后按云函数名作废 ──► 下一屏 onShow 仍调原接口，此时未命中，会出网

仅跳页/返回 ──► 同样的读 key 命中 ──► 0 次云函数

App 从后台回来 ──► 旗标 + 第一次物资域读时打 activity.cursor（全进程合并成 1 次）
                 ├ 水位没变：物资缓存保留
                 └ 水位变了：只作废物资域，这次读出网，其余同 key 仍可命中新结果
```

空间/标签没有 activities。本机改空间/标签走「写成功作废」；家人改名要等到回前台也**不会**因 cursor 发现（日志没有），本波不保证。

临期（S905）：`listExpiring` 的缓存 key 带上海时区当天日期。过零点 key 变，自然未命中，不必页面重算策略。

## 4. 缓存键与内存

- 作用域：进程内存。冷启动为空。切家/离开时整表清空。
- key：`familyId | 云函数名 | action | 稳定序列化(业务参数)`  
  `familyId` 取 `globalData.familyId`（或 `family._id`）。尚无家庭时**不缓存**，直接出网。
- 参数：去掉 `action`；对象 key 排序后 `JSON.stringify`。`undefined` 与缺省视为相同。
- `listExpiring` 额外拼 `today=YYYY-MM-DD`（上海）。
- `tag.ensureDefaults` 与 `tag.list` **共用** `tag | list | {}`，避免种子接口和列表各打各的。
- 失败不入缓存。同 key 并发只打一次云函数。
- 不设短 TTL。同会话内：未作废且未过日的读一直有效；家人改物资只靠回前台 cursor。

## 5. 策略表（唯一业务知识）

写在 `cloud.js`（或紧邻的 `queryCache` 配置）。按**云函数 + action**，不按页面、不按字段。

### 读（可缓存）

| 函数 | action | 备注 |
|------|--------|------|
| family | `getMyFamily` `listMyFamilies` | 与现有 `globalData.family` 并存；调用层命中即可少打 |
| item | `get` `search` `list` `count` `listExpiring` | |
| space | `list` `listLocations` `listItemsBySpace` | |
| tag | `list` `ensureDefaults` | 共享 list 键 |
| activity | `list` | 消息/详情最近操作 |
| activity | `cursor` | **不缓存结果**；只作探针，且全进程 inflight 合并 |

未登记的读：默认出网、不缓存（安全）。

### 写（出网 + 作废）

作废用粗粒度，避免缓存层理解字段：

| 写成功 | 作废 |
|--------|------|
| `item`：`create` `update` `remove` | 全部 `item` 读 + `activity` 读 + `space.listItemsBySpace` |
| `space`：一切非上表读（含 `ensureDefault`、位置 CRUD） | 全部 `space` 读 |
| `tag`：一切非 `list`/`ensureDefaults` | 全部 `tag` 读（含共享的 list 键） |
| `family`：`create` `join` `leave` `switchFamily` | **整表清空** |
| `family`：`updateBackground` `updateExpireReminder` | 仅 family 读（`getMyFamily` / `listMyFamilies`） |
| `family`：`recordSubscribeExpire` | 不作废列表 |

未登记的写：默认 **整表清空**（宁可多重打，不要脏读）。

写的返回值不负责填物资列表缓存；下一屏 `onShow` 未命中再拉。切家后 `getMyFamily` 可用返回体写入对应 key，属优化，非必须。

## 6. 回前台探针

`app.js` 只维护旗标，不调用业务云函数：

- 冷启动第一次 `onShow`：不探（缓存本空，页面会正常拉）。
- `onHide`：记「曾经进过后台」。
- 之后的 `onShow`：置 `needsItemRevalidate = true`。

`cloud.js` 在处理 **item 读**、**activity.list**、**space.listItemsBySpace** 之前：

1. 若无 `needsItemRevalidate`，按普通缓存走。
2. 若有：全进程只发一次 `activity.cursor`；与本地记住的 `{ latestId, latestAt }` 比较。
3. 相同或 cursor 失败：**保缓存**（失败开放，优先额度）。
4. 不同：作废物资域（同 item 写成功那一行），再让本次读取出网。
5. 清掉旗标；记下新水位。

`cursor` 实现：鉴权与 `list` 相同，`activities` 按 `familyId + createdAt desc` **limit 1**，只返回 `_id` 与 `createdAt`，不查昵称、不拉一页。

本机刚写过物资时缓存已空，回前台 cursor 即使再作废一次也只是空操作。

## 7. 按场景的决策

| 场景 | 决策 |
|------|------|
| S101～S102 冷启动会话 | 不缓存无 familyId 的读；onboarding 清会话本波不改 |
| S103 首页 ensureSession | `getMyFamily` 走 `callFamily` 后可命中 |
| S104 家庭页首次 | 照打；若会话已拉过 `getMyFamily` 则该键命中，仍可能打 `listMyFamilies` |
| S105 回家庭页 | 页面已跳过；调用层不依赖此跳过 |
| S201～S205 回首页 | 未写、未回前台 → 各读命中，**0 次** |
| S206 换空间筛选 | `search` 带 `spaceId`，不同 key；未命中才打 |
| S301～S305 详情再次 show | 命中则 0 次；从编辑保存回来因 item 写作废，本屏出网 |
| S401～S404 编辑 | 空间/标签若首页已拉过则命中；换空间 `listLocations` 按 spaceId 分键 |
| S501～S502 空间 | 同「跳页命中」 |
| S601～S602 标签/消息 | 命中则 0 次出网；页面 loading 快闪接受 |
| S701 口袋 | 自动吃 `list` / `listItemsBySpace` 缓存；无入口不单做 |
| S801 ensureDefault | 写成功作废 space 读，紧接着的 `list` 出网（正确） |
| S802～S807 写完再 load | 已作废 → 出网；不再「没改也打」 |
| S808～S812 家庭写 | 切家/离开清空；主题/总开关只作废 family 读 |
| S901 家人改物资 | 回前台 cursor 变了才作废物资域 |
| S902～S904 家人改名/主题 | 本波不保证 |
| S905 过零点 | `listExpiring` key 含日期 |
| S906 日志没写上 | 接受，可能漏一次 |
| S907 只改订阅 | `recordSubscribeExpire` 不作废；详情 `item.get` 仍可能旧到回前台或自己再打开编辑。本波接受（开关不是列表热点） |
| S908 定时推送 | 无关 |
| S909 停在当前页 | 无实时；不改页面 |

额度预期（同会话、未切后台）：

- 首页 → 详情 → 返回：约 9～11 次 → **首次 4～6，之后 0**
- 切出微信再回来、物资没变：**+1**（cursor）
- 物资变了：+1 cursor + 本屏物资相关读

## 8. 实施顺序

1. `queryCache.js` + `cloud.js` 策略表（先读缓存、写作废，**先不接 cursor**）。此时跳页已能省额度。
2. `session.js` 改走 `callFamily`。
3. `activity.cursor` + `app.js` 旗标 + `cloud.js` 探针。
4. 用场景 D 的组合路径在开发者工具看 Network / 云函数日志：返回首页、返回详情、切后台，对照次数。

不改页面，验收只能看**云函数调用次数**和「自己改完返回仍能看到新数据」，不能看代码里是否少了 `load()`。
