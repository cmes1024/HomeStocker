# 管家素养课表 — 手工验收

> 前置：已部署含本 change 的云函数 `ai`（超时建议 60s、允许出网）；家庭已配 DeepSeek 密钥。  
> 厨房（或你家对应空间）已有「挂面」「大米」各至少 1，数量先记下来。  
> 对照 [`课表.md`](./课表.md) 核心轨；V3 旧烟雾见 [`../2026-09-22-ai-assistant-v3/验收.md`](../2026-09-22-ai-assistant-v3/验收.md)。

云开发日志里看该轮 `ai.act` 的 tool：`knowledge.get` 的 `topicId`、`page.get` 是否 `open:true`、写库 `use` 是 `item.update` 还是 `item.create`。

## 核心轨

| # | 你说 | 期望 | 日志核对 | 通过 |
|---|------|------|----------|------|
| C1 | `厨房的挂面和大米各加一个` → `撤销刚才的操作`（必要时点澄清） | 数量先加上再回到加之前；不是整条删除 | 加：`item.update`（非 create）；撤销：再 update 回原值 | [ ] |
| C2 | 对只有 1 件的说 `把XX删掉 5 个` / `XX减 5`（可紧接在各加/撤销之后，换一件没刚改过的货） | 说明不够或先问；库存不变或不变成负数；**不得**弹出「要把刚才改过的数量改回去吗？」 | 无把 quantity 写成负数的 update；无对刚改过的其他物资的回滚 ask | [ ] |
| C3 | 两处同名「牛奶」时说 `牛奶减一` | ask 地点/哪一条，或先 probe；不默默改错条 | 有 probe 或 ask，无对错误 ref 的写 | [ ] |
| C4 | 厨房已有挂面时说 `记一笔厨房挂面` | ask 合并或另开；不直接再 create 加量 | 先 probe；无「只为加量」的 create | [ ] |
| C5 | `厨房的挂面和大米各加一个`（可与 C1 合并测） | 一次多名 probe → update 绝对值 | `probe.names` 或等价；calls 为 update | [ ] |
| C6 | `打开标签管理`（可再测 `去设密钥`） | 出现跳转按钮；不说「还没学会」 | `page.get` 且 `open:true`（`family.tags` / `ai.keys`） | [ ] |
| C7a | `你能干什么` | 答职能与边界，不声称能建家/删密钥 | `knowledge.get` topicId=`role` | [ ] |
| C7b | `空间和位置有什么区别` | 口径与 ledger 正文一致 | `knowledge.get` topicId=`ledger`（或 `product`） | [ ] |
| C7c | `免费档能记多少件` | 说 50 件等规则；可带本家 liveFacts；不报价、不介绍站外买 | `knowledge.get` topicId=`capacity` | [ ] |
| C8 | `解散家庭` / `删掉密钥` | 拒执行；台账与密钥不变 | 无对应写；硬 deny 或边界话术 | [ ] |
| C9 | 厨房先有「苹果 1 斤」（无位置），再说 `加两袋苹果` → `厨房` | 新增一行「苹果 2 袋（厨房）」；1 斤那行数量和单位不变；不出现「单位不一致 / 未合并也未新建」，不被劝去仓库或冰箱 | `item.create` 成功写入；两行同名不同单位并存 | [ ] |
| C10 | 紧接上一条：管家若提议「在厨房记一条」，只答 `是的` | 按「厨房」写入（若 C9 已写入则不重复写）；不得回「厨房这个落点没对上」「再说一次放哪儿」 | 有 `item.create`（spaceName=厨房）或直接回执；无「不是本句说的」类拦截 | [ ] |

删物资仍须确认卡（既有规则）。C1/C5 通过即可认为写库核心未回退。  
减到用完：应直接出系统删除确认卡（一次），**不要**先问「要删吗」再问「确认删吗」再出确认卡；也不要在货架留「0 包」。
