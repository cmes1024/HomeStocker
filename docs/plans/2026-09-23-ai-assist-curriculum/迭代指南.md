# 家庭管家 — 迭代与排查指南

对话翻车，先对这三类，再动代码。不要先加「说 xxx 就做 xxx」。

| 类型 | 含义 | 正确修法 |
|------|------|----------|
| **1. 信息不够** | 模型没看见往来、库存、目录、回执、接口语义 | 把事实送进 messages / 回灌 / hint 说明书 |
| **2. 私自决定并执行** | 代码按句子或空计划猜意图，自己拼 ask/calls | 删掉那段决策，让模型再编 |
| **3. 拦截或忽略模型的计划** | 模型已经 probe / update / page.get / remove，代码改写、丢掉或顶掉 | 执行它的下一手；闸门只拦硬边界（确认、HARD_DENY、quantity>0） |

意图、衔接、选工具是模型的事。我们只保证事实在、通道通、闸门硬。

云函数日志：`[ai.act] >>> system / history / user` 和 `<<< model`。先对「模型拿到了什么、交出了什么、我们有没有照做」。

---

## 红线

| 禁止 | 实际是哪一类 |
|------|----------------|
| prompt / hint 写「说饿了就 probe」「好的=执行上一轮」「各加必须 update」 | 用口诀掩盖 **1**，还常夹带 **2** |
| 正则 / 芯片文案映射成必须走某接口 | **2** |
| 空计划时代码合成「要不要撤销」 | **2** |
| 失败后叠确认、把 update 0 改写成 delete、丢掉 page.get | **3** |

课表（`课表.md`）是人看的考试，不是运行时路由。

## 各模块是干什么的

只列职责。职责以外的事，不要塞进这一层。

### 1. 小程序 `packageAiAssist`

- **做：** 收集本句、拼 transcript `history`（最多 20 轮）、可选 `focusItemId`；画气泡、芯片、确认卡、跳转按钮；确认后带 `confirmed + calls` 再打 `ai.act`。
- **不做：** 不读句子选接口；点芯片只把原文交给 `act`。
- **出问题先看：** 上一轮助手话有没有进 `history`；确认重放有没有丢 `calls`；气泡是否把同一句失败画了两遍。

### 2. 编排 `ai/agent/orchestrator.js`

- **做：** 身份与密钥 → 组上下文 → 问模型 → 按计划跑 probe / 白名单 tool → 确认闸门 → 写库或回 ask/done。
- **不做：** 不解析用户词；不把空计划解释成某个场景。
- **出问题先看：** 二次问模型时，本句是否仍是孤零零几个字、事实（PROBE / 目录 / 回执）有没有进 **user 或 messages**；idle / 确认有没有劫持计划。

### 3. 上下文与模型请求 `context.js` + `model.js` + `index.js` `callDeepSeek`

- **做：** system 里放人格、边界、树、能力表、知识**目录**；**往来作为 user/assistant 消息轮**接在当前句前面。
- **不做：** 不把整本知识、整份页面注册表打进每一轮 system。
- **出问题先看：** 日志里 `>>> history` 是否包含上一轮问答；当前 `>>> user` 是不是只有「好的」而 history 为空。短答应接不上，**优先修消息轮次**，不要写「好的=同意」。

### 4. Prompt `promptAssist.js`

- **做：** 人格、通道（ask / probe / calls / reply）、业务边界（范围外、未学会、quantity>0、不臆造、短号不明就问）。改了要 bump `ASSIST_PROMPT_VERSION`。
- **不做：** 场景口诀、代表形对话、话术→JSON 对照表。
- **出问题先看：** 只有通道真的坏了（模型交空计划、reply 冒充已写入、和 calls 抢道）才改这里。

### 5. 能力表 hint `capabilities.js`

- **做：** 给模型看的**接口说明书**：这个 id 是什么、参数什么意思、硬限制（绝对值、须确认、本版关闭）。bump `CAPABILITY_VERSION`。
- **不做：** 「何时用户说什么该用」；与对话场景无关。
- **出问题先看：** 模型是否把 `create` 理解成加量、把 `quantity` 理解成增量。那是**接口语义**不清。家人具体说了哪句，不构成改 hint 的理由。

### 6. 知识包 `knowledge/*` + `knowledge.get`

- **做：** 产品 / 职能 / 台账概念 / 容量口径。目录常驻，正文按需取。改正文 bump 该 topic `version`。
- **不做：** 办事步骤、场景剧本。
- **出问题先看：** 说错「空间和位置」「自己会不会删密钥」「免费档多少件」——改对应 topic，不要写进 prompt。

### 7. 查库 `probe` / `item.search` / `itemsQuery.js`

- **做：** 本轮库存事实 → P* 短号。树里没有物资行，查库是唯一库存来源。
- **不做：** 不按话术决定查哪个空间。
- **出问题先看：** 模型有没有 probe/search；结果有没有回灌再编。没看见库存就 create / 报数，是**事实没给到**，不是缺一句「先查再改」。

### 8. 页面 `pages/index.js` + `page.get`

- **做：** 可直达页的白名单；无 pageId / 未知 id 回目录；`open:true` 才出跳转按钮。禁止臆造 path。
- **不做：** 「去设密钥就打开某某页」的口诀。
- **出问题先看：** 模型是否拿到过目录；猜错的 id 有没有回到目录让它重编。不要按话术写死 pageId。

### 9. 工具与写路径 `tools/*` → `item` / `space` / `tag`

- **做：** 执行计划；确认闸门；quantity>0；HARD_DENY（`family.*` / `ai.*` 密钥）；`source: agent`。不另套领域模型。
- **不做：** 把 update 0 改写成 delete、按句子改计划。
- **出问题先看：** 计划本身要写什么；闸门有没有拦错；回执文案够不够模型下一轮接着用。

### 10. 展示 `presentation.js` + 客户端气泡

- **做：** 把执行结果画成卡片/按钮。不决策。
- **出问题先看：** 同一句失败是否正文+错误卡各画一次。

## 出了问题先查哪

先标 1 / 2 / 3，再选模块。

| 你看见 | 类型 | 先查 | 不要 |
|--------|------|------|------|
| 短答应接不上上一轮 | **1** | `history` 是否作为 messages | 「同意就执行提议」 |
| 没查库存就报数 / 就 create | **1** | probe/search 有没有跑、有没有回灌 | 「说记一笔必须先 probe」 |
| create 当加量、update 当增量 | **1** | 当前量在不在；hint 是否写明绝对值 | 「各加必须 update」 |
| 打开了不存在的 pageId | **1** | 目录有没有回到模型手里 | 「去设密钥就 open ai.keys」 |
| 说错产品 / 职能 / 限额 | **1** | 有没有 `knowledge.get`；正文对不对 | 口径抄进常驻 prompt |
| 空计划 / 甩范围外套话 | **1** | 是不是只看见本句 | idle 里教场景 |
| 空计划被合成「要不要撤销」 | **2** | 编排有没有替模型编 ask/calls | 再加合成问句 |
| 芯片点选被正则改成另一条接口 | **2** | 客户端/编排有没有读句子 | 话术表 |
| 模型要 remove，被改成先问再问 | **3** | 计划 calls 有没有被改写 | 叠确认 |
| 模型要 page.get open，失败后不再给目录 | **3** 或 **1** | 未知 id 有没有回灌目录再让它编 | 口头指路顶掉 open |
| 模型要 update，代码改成 remove 或丢掉 | **3** | 执行器是否改写了计划 | 失败改写器 |
| 代删密钥、代解散 | 闸门（该拦） | `HARD_DENY` | 按那句话写拒答正则 |
| 未确认就删/合并 | 闸门（该拦） | `confirm` | 再加一轮「要删吗」 |
| 跨家能写 | 闸门（该拦） | `resolveFamilyContext` | — |

日志不够就先补日志，不要补口诀。

## 改哪一层（只改事实或闸门时）

1. **口径错**（空间≠位置、免费档件数）→ 知识包，bump topic version。  
2. **接口语义错**（create 是新行、quantity 是绝对值）→ 该 id 的 hint，bump 能力表 version。与用户怎么说无关。  
3. **通道坏了**（空计划、reply 冒充写入）→ prompt 通道/边界句，bump prompt version。仍禁止加场景。  
4. **闸门/身份/回执/消息轮次** → 代码。  
5. **模型看见了该看见的，仍办砸** → 记案例，不要立刻加口诀。先确认不是事实缺失。

改完只发需要覆盖 version 的云函数 `ai`（prompt / 能力表 / 知识包）。客户端协议没变就不必同发。
