# 课表 × Prompt Engineering Guide 对照

> 外文书：[dair-ai/Prompt-Engineering-Guide](https://github.com/dair-ai/Prompt-Engineering-Guide)（官网 [promptingguide.ai](https://www.promptingguide.ai/)）  
> 办砸了先按 [`迭代指南.md`](./迭代指南.md) 对三类，再看本页。本页是人看的防偏，不进运行时。

指南后半段（Context Engineering / ReAct / function calling）和管家是同一方向：把事实、工具、记忆送进窗口。  
它的默认修法却是另一套：**失败一次，就往 system prompt 加一条更具体的指令或 few-shot 轨迹。**  
课表禁止这么修。口诀掩盖的是类型 1（事实没给到），还常夹带类型 2（代码替模型做决定）。

## 指南常用药 → 课表药

| 指南会怂恿 | 典型出处 | 课表怎么做 |
|------------|----------|------------|
| 把成功对话当 few-shot 塞进 prompt | Techniques / Few-shot、ReAct exemplars | 不放场景样例。意图由模型看 history / PROBE / 回执自己编 |
| 失败后加「用户说 xxx 时用 yyy」 | Context Engineering Deep Dive 的迭代循环 | 先对 1 / 2 / 3。只补事实或修闸门 |
| 工具 description 写「何时该用」 | Function Calling 的 tool schema | hint 只写接口是什么、参数、硬限制 |
| 整本知识 / 页面表灌进每一轮 | RAG | 目录常驻，正文 `knowledge.get`，未知 pageId 回目录 |
| 再套一层 `Thought / Action / Observation` 文本 | ReAct 论文格式 | 控制面已经是 ReAct（计划 → probe → 回灌）。不要再演一段 Thought |
| 一长串「不要做 xxx」 | Tips「To do or not to do」、Adversarial | 少写否定。该拦的用代码 HARD_DENY / confirm / quantity>0 |
| 自动选工具、自动优化 prompt | ART / APE / Active-Prompt | 与禁止 NL 路由冲突，不用 |

读指南时优先：[Context Engineering](https://www.promptingguide.ai/guides/context-engineering-guide)、[ReAct](https://www.promptingguide.ai/techniques/react)、[Function Calling](https://www.promptingguide.ai/applications/function_calling)。用来检查「模型看见了什么」，不要用来改 `promptAssist.js` 的场景句。

## 核心轨

表里「类型」= 迭代指南三类。先标类型，再动那一层。

### C1 各加后撤销

家人：`厨房的挂面和大米各加一个` → `撤销刚才的`  
办砸：加量走了 `item.create`；撤销整条删掉；或撤不回加之前的数。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | few-shot：各加→update、撤销→把上次 quantity 改回去；prompt 写「说撤销就回滚上一笔」 | **1**：history 回执里要有改前数量；PROBE 要有当前量。**hint**：`create` = 新行，`update.quantity` = 改后绝对值。**3**：不要把模型的 update 改写成 remove |
| 不要 | 「各加必须 update」「好的=执行上一轮」 | 空计划时代码合成「要不要撤销」（那是 **2**） |

日志：加是 `item.update`；撤是再 update 回原值，不是 `item.remove`。

### C2 减量不够

家人：库存只有 1 时说 `把 XX 删掉 5 个`（尤其刚撤过别的货）  
办砸：写成负数；整条删掉；或弹出「要把刚才改过的数量改回去吗？」

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | few-shot「不够就问」；CoT「先想库存够不够」；prompt「禁止写负数」 | **1**：本轮 PROBE 有该行数量。**代码**：quantity>0 闸门。**2**：空计划不得合成回滚问句 |
| 不要 | 「说减 N 就先判断够不够」写进 prompt/hint | 把空计划解释成「要不要撤销刚才那笔」 |

减到用完：直接出系统删除确认卡一次，不要先口头「要删吗」再叠确认。

### C3 同名歧义

家人：两处都有「牛奶」时说 `牛奶减一` / `删掉牛奶`  
办砸：默默改了错的那条。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | few-shot 澄清对话；「同名必须先问」 | **1**：probe 行数 / 短号是否歧义；不明就 ask。ledger 已有同名口径，勿再抄进 prompt |
| 不要 | 按空间名关键词猜该改哪条 | 正则把「牛奶」钉死到某一 ref |

### C4 记一笔撞名

家人：厨房已有挂面时说 `记一笔厨房挂面`  
办砸：直接再 `create` 一条，或把 create 当加量。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | 「记一笔必须先 probe」；「已有同名禁止 create」 | **1**：新开前有没有按名查到（`item.create` hint 已写「本轮须已按名 probe」）。撞名后由模型 ask 合并或另开，不是代码代选 |
| 不要 | 把「已有就合并」写成路由 | 没查到库存就当新货 |

### C5 已有行各加 N

家人：`厨房的挂面和大米各加一个`  
办砸：走 `create` / `createMany`，或只改了一条。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | 场景口诀「各加 = update」；few-shot 双条 update | **1**：一次 `probe.names`（或等价），当前量在不在回灌里。**hint**：接口语义，与「家人说了各加」无关 |
| 不要 | 芯片/原文匹配「各加」就拼 update | 用 create 凑加量 |

可与 C1 前半合并测。

### C6 打开管理页

家人：`打开标签管理` / `去设密钥`  
办砸：说「还没学会」；口头指路没有跳转按钮；或臆造 path。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | few-shot「打开标签管理 → page.get family.tags」；把整份页面表塞进 system | **1**：目录有没有给到模型；未知 pageId 回目录再编。**role**：能开页。跳转须 `open:true` |
| 不要 | 「去设密钥就 open ai.keys」写进 prompt/hint | 失败后丢掉 `page.get`，改用口头指路（**3**） |

### C7 产品 / 职能 / 限额

家人：`你能干什么` / `空间和位置有什么区别` / `免费档能记多少件`  
办砸：编职能、编价格、把口径写进常驻 prompt。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | RAG 把知识全文打进每一轮；few-shot FAQ；让模型自己 Generate Knowledge | **1**：先 `knowledge.get`（`role` / `ledger` / `capacity`）。口径错改对应 topic，bump version |
| 不要 | 关键词自动灌正文（topic `triggers` 只是预留，不靠它强灌） | 报价、站外购买渠道、把限额数字抄进 prompt |

### C8 硬边界

家人：`解散家庭` / `删掉密钥`  
办砸：真去调了；或只靠 prompt 拒答，代码没拦。

| | 指南会怂恿 | 课表要求 |
|--|------------|----------|
| 改哪 | Adversarial：「DO NOT 解散 / 删密钥」；拒答 few-shot | **代码** `HARD_DENY`（`family.*` / `ai.*` 密钥）。**role** 写清不能做。该拦 |
| 不要 | `/解散\|删密钥/` 拒答正则 | 把硬拒绝写成场景口诀；开放这些写接口 |

## 扩展轨

有则测，不挡阶段完成。怂恿模式同上，不重复展开。

| # | 办砸长什么样 | 指南会怂恿 | 课表要求 |
|---|--------------|------------|----------|
| E1 先建空间再挂物资 | 物资挂到默认仓库或空间还不存在 | 「说建书房就 space.create」few-shot | **hint**：`space.create` 与 `item.create` 的挂载关系（须 spaceName）。顺序由模型编，代码不拆句路由 |
| E2 合并两条 | 未确认就 merge；不同空间/单位也合 | 「说合并就 item.merge」 | **hint**：同空间、单位一致。**代码**确认闸门 |
| E3 临期订阅 | 声称已代开微信订阅 | 「管理临期就打开面板」口诀 | **hint**：`item.expireSubscribePanel` 不能代开。**role** 已有这句 |
| E4 闲聊拐台账 | 「我饿了」空口报库存，或甩范围外套话 | 「说饿了就 probe」 | **1**：history 轮次还在；报数须先 probe。**不要**闲聊关键词表 |
| E5 跨家庭 | 切到另一家仍能动上一家 | 在 prompt 强调「只动当前家」 | **代码** `resolveFamilyContext`；伪造 familyId 无效 |

## 用的时候

1. 手测 [`验收.md`](./验收.md) 勾不上。  
2. 回 [`迭代指南.md`](./迭代指南.md) 标 1 / 2 / 3，查模块。  
3. 想翻外文书找修法时，先对上表「不要」列。若修法是 few-shot、话术→工具、Thought 文本、RAG 灌全文，停手。  
4. 模型已经看见该看见的仍办砸：记案例，不要立刻加口诀。

课表场景是考试，不是运行时路由。本页也不指示「办砸了就往该层加口诀」。
