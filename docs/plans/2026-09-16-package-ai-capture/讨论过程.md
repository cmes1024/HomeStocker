# 讨论过程（如何收敛到本方案）

> 目录：[`README.md`](./README.md)  
> 定稿：[方案.md](./方案.md)  
> 本文只记录 **为什么这样选**。实现细节以方案为准。

讨论发生在 2026-09-16。起点是：家庭物资小程序的主场景是增删改查，但不能指望用户把家里的东西一条条手建，商品最好有图、更具象；能否用 AI 接上现有写接口。

---

## 1. 最初设想

用户从首页 AI 浮窗进助手页：拍一张或多张照片，长按语音（「这个纸有 10 包，5 包厨房柜子、5 包玄关」「这个罐头保质期到 10 月 20」），提示词整理后直接调接口入账。

当时立刻暴露的三个风险：

1. **图和话对不齐**：「这个纸」对应哪一张。
2. **一句话拆两条台账**：现有模型是一条物资一个 `spaceId` + 一个 `locationId`，「10 包拆两处」不能记成一条再写备注。
3. **`items` 没有图片字段**；空间 `coverKey` 只是氛围，不是商品图。

同时对照了 9 月 7 日的 AI 设计：那是半屏聊天、一句一条、不要图、不要批量。和这次「拍照入账」不是同一档产品。

---

## 2. 绑死「一行一物」

用户改为：照片分行展示，**每一行自己的语音按钮**，转写进该行输入框，可手改；统一确认后再给模型；卡片预览，再确认才保存。

这拿掉了跨图指代，也把「10 包拆两处」从主路径拿掉：一行默认一条台账。若同一行里仍说出分放，当作异常（进备注或卡片上让人改），不在 V1 自动拆条。

页面形态从「聊天」改成 **三步向导**：采集 → 识别 → 预览保存。旧 `pages/chat` 不复活。

---

## 3. 模型吃什么、吐什么

一度讨论过视觉理解（看图识物、OCR 保质期）。用户明确：

- **第一版不对图做识别，只落图。**
- **物品信息以语音（转写后可改的文字）为主。**
- **只有图没有文字的行不处理。**

模型因此从多模态退回文本 JSON 抽取，成本、超时、绑定都简单得多。

字段约定：

- 模型 **只出名称、数量、空间名、位置名等，不出数据库 `_id`**（id 幻觉严重）。
- 代码用当前家庭的空间 / 位置 / 标签目录做解析。
- 空间、标签 **不自动新建**；位置没有时卡片提示「将新建」，保存时再 `createLocation`。
- 图与话冲突时本可规定优先级；V1 无视觉后，只以该行文字为准，图仅封面。

提示词：**放数据库，云函数读取**。曾设想缓存到本地再由端上带着提示词去调模型——与 BYOK、合法域名、密钥安全冲突后否决（见 §5）。

---

## 4. 预览与放弃

用户指定预览交互（已锁定）：

- 每张卡片可勾 **「放弃录入」**。
- 只要还有未放弃的 → 底栏 **「确认录入 n 个物品」**。
- 全部放弃 → 底栏变成 **「放弃本次录入」**，不写库、不传图。

识别与写入是两道闸：没核对的 JSON 不能进 `item.create`。模型不能直接写库。

---

## 5. 谁调模型、key 放哪

比较过三条路：

| 路 | 结论 |
|----|------|
| 小程序直连用户 key | 否。合法域名、key 在端上、换模型要改客户端。 |
| 云开发 `wx.cloud.extend.AI` | 对对话/流式最顺，但是 **环境级额度**，对不上「这家用这把 key」。 |
| **云函数 axios 出网代发** | **采用。** 不配合法域名；`chatProxy` 已有 axios 先例；超时调到 20–60 秒够一次 JSON 抽取。 |

云函数擅长一次请求整段 JSON，不适合塞 LangGraph。长线助手仍是：云函数注入身份，脑子放独立服务。本版不上那个。

Key 的归属演进：

1. 每人一把 → 配偶没有 DeepSeek 就无法录入。
2. **改成家庭级，可配多把，家里的人都能用。** 与「一本账、全员同权」一致。
3. **默认一把，失败再换**（401 / 余额不足 / 429），不必每次录入选手动选模型。
4. 端上列表 **只显示掩码**（后四位）。完整密钥只存在云函数可读存储。

厂家：曾讨论 DeepSeek / 通义 / 自定义都要填 `baseUrl` + `model`。最终 **第一版只预设 DeepSeek**，界面只贴 key；`baseUrl` / `model` 由系统写入，方便以后加预设却不改表。

合并 vs 逐条调模型：V1 无图、文本很短，**一次请求按行号打包**，提示词只走一遍；以后若看图再改回逐张。

---

## 6. 对现有业务零侵入

用户要求：AI 是现有业务的分支，理论上不改现有业务代码。

收敛为：

- 能力都在 **`packageAi` 分包** + 新云函数 `ai`。
- 保存只 **调用** 现有 `item.create`（`source: 'agent'`）和必要时的 `space.createLocation`。
- 图不进 `items` 字段，走 **旁路集合**；清单第一版仍纯文字。
- 允许的「挂钩」只有入口和密钥生命周期，见方案 §2。不把识别、提示词、语音织进清单或编辑页。

曾考虑给 `item.create` 加图片字段以便列表立刻有图——为守住零侵入而推迟。具象化留在助手预览；列表出图是后续单独增量。

---

## 7. 明确否决（不要在实现时翻案）

- 半屏聊天气泡作为本版入口。
- 视觉识别 / OCR 进模型。
- 客户端拼提示词、客户端持有完整 API Key、客户端 `wx.request` 打 DeepSeek。
- 模型直接写数据库，或 `ai` 云函数复制一套 `item.create` 校验。
- 自动新建空间或标签。
- 识别阶段合并已有同名物资、改库存。
- 把 LangGraph / `agent/` 接到本版向导。
- 复活产品路径上的 `pages/chat`。
- 为 AI 改清单 `onShow`、筛选、编辑表单、`cloud.js` 策略表（入账走 `callItem` 即可）。

---

## 8. 仍后置、本版不写进任务

- 查询对话（「家里还有牛奶吗」）。
- 流式输出。
- 第二家模型预设。
- 清单/详情展示封面图。
- 录入前确认弹窗以外的撤销/回滚事务（逐条 create，失败停在当条）。

后记：同一行若写清各处数量（「厨房冰箱 2 瓶、客厅 1 瓶」），抽取改为按空间拆成多张预览卡片；不再把总数塞进第一处。
