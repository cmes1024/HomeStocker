## 1. 目标

在不改现有清单/编辑主路径的前提下，提供一条家庭共享的 AI 录入支路：

1. 拍照分行，每行语音转文字（可手改）。
2. 有文字的行合并一次，由云函数带提示词 + 家庭目录调用 DeepSeek，得到可预览的物资草稿。
3. 用户可放弃部分或全部；确认后逐个走现有写接口入账。
4. 图片上传云存储并挂到旁路集合；第一版清单不展示该图。

成功标准：不会用手填表的人，能用「拍 + 说 + 核对」把多件东西记进当前家庭；回到首页能看到新物资（走现有 `onShow` + 写作废）。

## 2. 耦合边界

```
现有业务页 / db.js / item·space·tag 云函数
        │  仅被调用，不理解 AI
        ▼
  callItem / callSpace          ← 已有；create 成功会作废物资缓存
        ▲
        │
packageAi 页面 ──► 云函数 ai     ← 新：密钥、提示词、代发模型、挂图
```

### 2.1 允许改动的文件（白名单）

| 位置 | 改什么 |
|------|--------|
| `miniprogram/app.json` | 注册 `packageAi` 分包；如需同声传译则加插件声明 |
| `miniprogram/pages/items/index.*` | **只加** AI 浮窗，`navigateTo` 进分包。不改拉数、筛选、空态主按钮逻辑 |
| `miniprogram/pages/family/index.*` | **可选一行**「AI 额度」进入分包密钥页 |
| `miniprogram/cloudfunctions/ai/` | **新建** |
| `miniprogram/packageAi/` | **新建**全部页面与分包内工具 |
| `miniprogram/cloudfunctions/family/index.js` | **仅解散路径**增加删除 `familyAiKeys` / `itemMedia`（密钥与孤儿文件生命周期，与现有 tags/activities 清理同类） |
| `miniprogram/cloud/database-rules.json` 与 `collections.md` | 新集合规则与字段说明 |
| 本目录文档 | 同步 |

### 2.2 禁止改动

- `pages/items/edit`、详情、空间/标签/消息页的业务逻辑
- `cloudfunctions/item` 的 create/update/remove 语义（客户端照旧传 `source: 'agent'`）
- `utils/cloud.js` / `queryCache.js`（AI 读密钥/提示词用分包自己的调用封装）
- 把提示词、模型名、语音 SDK 写进清单页
- 产品导航复活 `pages/chat` / `pages/demo`

无密钥时：助手页引导去配 key，不必先改家庭页。家庭页那一行是发现性，不是功能依赖。

## 3. 用户动线

```
首页浮窗 ──► packageAi 采集
                │
     选图（1～N）→ 一行：缩略图 + 输入框 + 本行语音键
                │
     没字的行：开始识别时跳过（可 toast「n 行没说话，已跳过」）
     全没字：不允许识别
                │
                ▼
           云函数 ai.extract（一次，按 index 打包）
                │
                ▼
           预览卡片（与照片行绑定）
           □ 放弃录入
                │
     未放弃 n≥1 → 「确认录入 n 个物品」
     全部放弃   → 「放弃本次录入」（返回，零写入）
                │
                ▼
     对未放弃项逐个：
       需要时 space.createLocation
       item.create { source: 'agent', ... }
       上传图片 → ai.attachMedia
```

采集页语音：微信同声传译（WechatSI）或当前官方等价插件，**只得到文字**，不把音频送模型。

## 4. 架构

```
小程序 packageAi
  采集 / 预览 / 密钥配置（掩码）
           │
           │  文字行[] + 当前家庭上下文由服务端自取
           ▼
云函数 ai（OPENID + currentFamilyId + membership）
  ├─ keys：增删、设默认、列表（掩码）
  ├─ extract：读提示词 + 目录 + 默认 key 调 DeepSeek，失败换下一把
  └─ attachMedia：校验该 item 属于本家后写 itemMedia
           │
           ▼
https://api.deepseek.com/v1/chat/completions
           │
           ▼
JSON 数组（按 index）──► 端上卡片 ──► callItem / callSpace
```

身份：只信云函数 `OPENID`，与现有 family/item 相同。抽取请求里不要带 `familyId` 覆盖项；即使用户传了也忽略。

云函数超时：控制台改为 **60 秒**；内部 HTTP **约 45 秒**。普通 `callFunction` 不流式，本版整段返回。

## 5. 数据

客户端对这些新集合 **写 deny**，与 `items` 一样只走云函数。

### 5.1 `familyAiKeys`

家庭模型网关档案。不要把明文 key 放进 `getMyFamily`。

| 字段 | 说明 |
|------|------|
| `_id` | 自动 |
| `familyId` | 隔离 |
| `provider` | V1 恒为 `deepseek` |
| `label` | 显示名，默认「DeepSeek」 |
| `baseUrl` | 系统写入 `https://api.deepseek.com/v1`，界面不展示、不允许用户改 |
| `model` | 系统写入 `deepseek-chat` |
| `apiKey` | 明文只存在本集合；**任何给客户端的接口必须脱敏** |
| `isDefault` | 布尔；一家同时只允许一把默认（写入时把其它张打成 false） |
| `createdBy` | openid |
| `createdAt` / `updatedAt` | 时间戳 |

上限 **3** 把。全员同权可增删（与主题开关相同）；界面文案写明这是全家额度。

列表返回：`_id`、`provider`、`label`、`model`、`isDefault`、`keyHint`（如 `sk-…8f2a`）、时间。永不回 `apiKey`、完整 `baseUrl` 也可以回（非秘密），但 V1 预设下回不回都行。

索引：`familyId`。

### 5.2 `aiPrompts`

应用级提示词，不是按家庭一份。

| 字段 | 说明 |
|------|------|
| `_id` | 稳定 id，V1 用 `item-extract-v1` |
| `version` | 数字，变更后 extract 用最新 |
| `system` | 系统提示词全文 |
| `updatedAt` | |

只有运营/开发在控制台改这篇文档，小程序不做提示词编辑器。extract **每次从库读取**（或云函数内存短缓存），不要依赖端上缓存提示词。

提示词必须注入：今天日期（Asia/Shanghai，含星期）、当前家庭空间名列表、各空间下位置名、标签名。规则要点：

- 只输出 JSON（可用 DeepSeek `response_format: json_object` 包一层 `{ "items": [ ... ] }`）。
- 每项带 `index` 对应入参行号。同一物资分放到不同空间且各处有数量、或一行里明确说了两个商品时，同一 `index` 可出多项。
- 数量拆成数字 + 单位（两=2；一箱12瓶记 12 瓶）；相对日期按「今天」换算；「10 月 20」今年已过则明年。
- 空间是房间/功能区，位置是冰箱/柜子等；「厨房冰箱」不得整段当空间名。没说放哪则 `spaceName` 空（端上落到默认空间），不要擅自填「仓库」。
- 空间/位置/标签用目录里的 **原名** 或最接近的一个；对不上空间则 `spaceName` 空；对不上位置则原样给出 `locationName` 并 `createLocationIfMissing: true`。
- 不要编造目录里没有的标签名（对不上则 `tagNames: []`）。
- 缺数量则 `quantity: 1`。名称为空则该项应能被端上拦截（不可保存）。

### 5.3 `itemMedia`（旁路图）

| 字段 | 说明 |
|------|------|
| `_id` | 自动 |
| `familyId` | |
| `itemId` | |
| `fileID` | 云存储 fileID |
| `createdAt` | |

V1 一件物资一封面即可（重复 attach 覆盖或拒绝第二张，实现时选简单的一种并写进代码注释）。解散家庭时与 key 一并删；云存储文件 best-effort `deleteFile`。

索引：`itemId`；`familyId`（解散）。

### 5.4 现有 `items`

不改 schema。`source: 'agent'` 已支持。清单不读 `itemMedia`。

## 6. 云函数 `ai` 的 action

鉴权一律：`OPENID` → `users.currentFamilyId` → `memberships`，失败则与 item 云函数同类错误码。

| action | 说明 |
|--------|------|
| `listKeys` | 掩码列表 |
| `addKey` | 入参仅 `apiKey`、可选 `label`。服务端填 DeepSeek 预设。第一把自动默认 |
| `removeKey` | 若删的是默认且还剩其它，把最早创建的一把设为默认 |
| `setDefaultKey` | |
| `extract` | 见 §7 |
| `attachMedia` | `{ itemId, fileID }`，校验 item 属本家 |

不要提供 `updateKey` 改 baseUrl。换 key = 删了再加。

## 7. extract 契约

**入参（客户端）：**

```json
{
  "rows": [
    { "index": 1, "text": "这个纸有10包，放厨房柜子" },
    { "index": 2, "text": "这个罐头保质期到10月20" }
  ]
}
```

去掉空白行。`index` 必须与采集行一致，预览靠它绑回照片。建议上限 9（与一次选图张数一致）。同一行若把同一物资按空间分开放并给出各处数量，服务端可对同一 `index` 返回多张草稿（共用该行照片）。

**服务端还会自行读取：** 提示词、空间/位置/标签目录、`familyAiKeys`（默认优先，失败按 `createdAt` 再试其它）。

**模型出参（规范化后给客户端）：**

```json
{
  "drafts": [
    {
      "index": 1,
      "name": "抽纸",
      "quantity": 10,
      "unit": "包",
      "spaceName": "厨房",
      "spaceId": "实际id或空",
      "locationName": "柜子",
      "locationId": "实际id或空",
      "willCreateLocation": true,
      "tagIds": [],
      "tagNames": [],
      "expireDate": null,
      "productionDate": null,
      "note": "",
      "error": null
    }
  ],
  "providerTried": ["deepseek"]
}
```

解析规则（代码，不靠模型给 id）：

1. `spaceName` 与本家 `spaces.name` 精确匹配，否则包含匹配；再没有 → `spaceId` = 默认仓库（`isDefault` 或名为「仓库」的那个），卡片标「地点按仓库，请改」。
2. 在该 `spaceId` 下匹配 `locations.name`；没有 → `locationId` 空，`willCreateLocation: true`（`locationName` 非空时）。位置名为空则不建位置。
3. `tagNames` 精确匹配本家标签，得到 `tagIds`，其余丢弃。
4. 日期已是 `YYYY-MM-DD` 才收下，否则置空。
5. 某行模型漏了 `index` 或 JSON 整包失败：该行 `error` 文案，其它行仍返回。整包失败则换下一把 key 整包重试一次；都失败则 extract 返回业务错误，端上停留在采集或显示「识别失败」。

**保存（客户端，非 extract）：**

对未放弃且 `name` 非空的草稿：

1. 若 `willCreateLocation`：`callSpace('createLocation', { spaceId, name: locationName })`，用返回 id。
2. `callItem('create', { name, quantity, unit, note, spaceId, locationId, tagIds, productionDate, expireDate, source: 'agent' })`。
3. 该行本地临时图：`wx.cloud.uploadFile`，再 `ai.attachMedia`。
4. 按预览顺序逐个进行；某一件失败则停，已成功的保留，提示「已录入 x 件，第 y 件失败」。

不要在 `ai` 里批量写 items。

## 8. DeepSeek 预设与 failover

写死在云函数常量（与库字段一致）：

- `baseUrl`: `https://api.deepseek.com/v1`
- `model`: `deepseek-chat`
- path: `POST {baseUrl}/chat/completions`
- `response_format`: `{ "type": "json_object" }`
- `stream`: false

Failover 触发：HTTP 401、402、429、5xx，或网络超时。换下一把完整重试 extract（同一 `rows`）。一把成功就停。不要在两把之间混用半段结果。

无任何 key：extract 返回明确错误，端上引导配置。

日志：只打 key 后四位、status、耗时。禁止打 Authorization 头和提示词全文以外的密钥。

出网：云开发环境需允许云函数访问公网。

## 9. 分包页面

建议最少两页（名称可调整）：

| 页 | 职责 |
|----|------|
| `packageAi/capture/index` | 向导：采集 → 识别中 → 预览保存 |
| `packageAi/keys/index` | 家庭 DeepSeek key 列表 / 添加 / 删 / 设默认 |

主题：读 `globalData` 已有主题，套 AppShell，与全站一致。

选图：`wx.chooseMedia`，压缩后再作缩略图；原图或压缩图保存到行上，确认录入时再 upload。放弃的行不上传。

无家庭 / 无会话：与其它页一样先保证 `ensureSession`；无家则回 onboarding，不要在分包里创建家庭。

## 10. 安全

- 密钥不下发、不进 `wx.setStorage`。
- `addKey` 可对 key 做极轻校验（非空、长度），不要在端上打 DeepSeek 做「测试」——测试也走云函数，例如 extract 空跑或单独 `testKey`（V1 可省略测试按钮，加成功即可）。
- baseUrl 第一版不接受用户输入，避免 SSRF。
- `attachMedia` 必须校验 item 的 `familyId`。
- 解散：删除该家 `familyAiKeys`、`itemMedia`，并尽量删存储文件。普通成员离开 **不删** 家庭 key。

## 11. 明确不做（本 change）

- 视觉 / OCR 进模型
- 对话查询、流式、LangGraph
- 清单展示封面
- 自动建空间/标签、合并已有物资
- 第二模型预设、自定义 baseUrl
- 改 `item` 云函数字段
- 为 AI 单独做离线队列
