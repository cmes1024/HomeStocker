# 验收清单

对照 [方案.md](./方案.md)。未勾项视为未完成，不要用「页面能开」代替。

环境：已加入家庭、该家至少有默认空间「仓库」，建议再有一个「厨房」+ 位置「柜子」，以及至少一个默认标签。家庭里已配置至少一把有效 DeepSeek key。

---

## 入口与隔离

- [ ] 物资首页有 AI 浮窗，能进入 `packageAi`，返回后清单筛选/数据与进入前一致（无多余云函数刷屏也可，但至少功能不错乱）。
- [ ] 编辑物资、详情、空间、标签、消息页无 AI 逻辑、无新依赖。
- [ ] 产品 `app.json` 主包 pages 列表不恢复 `pages/chat`。
- [ ] 分包失败或未部署时，浮窗应有失败提示，不能拖垮首页 `onShow`。

## 密钥

- [ ] 添加 key 只需粘贴密钥（可选名称），不出现 baseUrl / 模型输入框。
- [ ] `listKeys` 与页面只有掩码，没有完整 key。
- [ ] 家庭成员 B 能使用成员 A 配置的 key 完成一次识别（额度在 A 的 DeepSeek 账上消耗）。
- [ ] 默认一把；删掉默认后仍剩的 key 会有新默认。
- [ ] 第四把添加失败。
- [ ] 无 key 时开始识别有明确引导，不出现 Axios 堆栈。

## 采集

- [ ] 可多选照片，一行一个缩略图。
- [ ] 每行独立语音，转写进入该行输入框，可手改。
- [ ] 只有图没有字的行不出现在识别结果里。
- [ ] 全部行为空文字时不能发起识别。

## 识别

- [ ] 两行有效文字一次识别得到两张卡片，index 与照片对应正确（纸的话不会写到罐头那张卡上）。
- [ ] 「10 月 20」类日期变成 `YYYY-MM-DD`（相对「今天」上海时区）。
- [ ] 说到已有空间/位置名称时，保存用的是目录 id，不是在库里新造同名空间。
- [ ] 说到不存在的位置时，卡片标明将新建；保存后该空间下出现该位置，且物资挂上。
- [ ] 不会自动新建空间或标签。
- [ ] 第一把 key 无效、第二把有效时识别仍能成功。

## 预览与保存

- [ ] 勾选放弃后，底栏在「确认录入 n 个物品」与「放弃本次录入」之间切换正确。
- [ ] 「放弃本次录入」之后：无新 items、无新 itemMedia、无新云存储文件。
- [ ] 确认录入只写入未放弃项；`items.source === 'agent'`。
- [ ] 家庭消息出现对应 create 记录。
- [ ] 回到首页能看到新物资（名称、数量），**不要求** 看到照片。
- [ ] 名称为空的卡片不能被写入。
- [ ] 连续两件时第二件 `item.create` 失败：第一件已存在，有明确失败提示。

## 生命周期

- [ ] 解散家庭后该家 `familyAiKeys`、`itemMedia` 被清掉。
- [ ] 普通成员离开不影响家里剩余成员继续用 key。
- [ ] 切换家庭后，识别与密钥列表作用于新的当前家。

## 回归（现有业务）

- [ ] 手填新建/编辑/删除物资仍可用。
- [ ] 空间、位置、标签 CRUD 仍可用。
- [ ] 过期横幅、订阅、消息流在「只用手填、不用 AI」时与改前一致。

## 安全抽查

- [ ] 云函数日志看不到完整 API Key。
- [ ] 小程序 Storage / 页面 data 调试看不到完整 API Key。
- [ ] 直接调用 `ai.attachMedia` 挂别人家的 itemId 应失败。
