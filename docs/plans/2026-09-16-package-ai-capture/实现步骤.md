# 实现步骤

> 权威行为：[方案.md](./方案.md)  
> 做完对照：[验收.md](./验收.md)  
> 约束：先 OpenSpec change，再按下列顺序改代码。未完成 OpenSpec 不要直接铺页面。

每一步结束时应能单独说明「怎样才算过」。不要并行大改 item/family 主路径。

---

## 0. 开工前（文档与规格）

1. 用 OpenSpec 建 change（名称建议 `package-ai-item-capture`），把本目录方案收成 proposal / design / spec / tasks，**不要手建 `openspec/changes/` 目录**。
2. 在 `collections.md` 草稿里列出新集合（真正改仓库文件可与步骤 1 一起做）。
3. 云开发控制台：确认云函数可出网；准备把新函数超时调到 60 秒。
4. DeepSeek 控制台准备一把测试 key（只用于开发家庭，不写进仓库）。

---

## 1. 空分包可跳转（无 AI）

**做：**

- `app.json` 增加分包 `packageAi`，先注册占位页。
- 首页 `pages/items/index` 增加浮窗，`navigateTo` 到占位页。
- 占位页用 AppShell，标题「AI 录入」，一句话说明后续能力。

**不做：** 语音、选图、云函数。

**过：** 真机/开发者工具从清单点浮窗能进分包并返回，清单筛选与拉数与改前一致。

---

## 2. 集合、规则、云函数骨架

**做：**

- 控制台创建 `familyAiKeys`、`aiPrompts`、`itemMedia`。
- `database-rules.json`：三集合客户端读可按项目惯例（建议读也 deny，一律云函数）；写 deny。
- 新建 `cloudfunctions/ai`（`wx-server-sdk` + `axios`），action 路由 + 与 item 相同的家庭鉴权辅助函数（可小范围复制，不要去改 item 文件抽公共包——避免扩散 diff；若已有可复用的云函数公共模块则用现成的）。
- 写入 `aiPrompts` 文档 `item-extract-v1`（系统提示词按方案 §5.2）。
- 部署 `ai`，超时 60s。

**过：** 未登录态/无家庭调任意 action 失败；控制台能看到提示词文档。

---

## 3. 家庭密钥

**做：**

- `listKeys` / `addKey` / `removeKey` / `setDefaultKey`，DeepSeek 预设写死。
- 分包页 `packageAi/keys`：列表掩码、添加（只输入 key + 可选名称）、删除、设默认。
- 家庭页可选加一行入口。
- 上限 3；第一把自动默认。

**过：** 两名成员都能看到同一掩码列表；`listKeys` 回包无 `apiKey` 字段；加第四把被拒。

---

## 4. extract 不含 UI

**做：**

- 实现 DeepSeek 调用 + JSON 解析 + 空间/位置/标签解析 + failover。
- 用云开发测试或临时脚本：传入两行中文，返回带 `spaceId` 的 drafts。
- 日志脱敏。

**过：** 无 key 时明确错误；一把 401、第二把有效时能成功；目录里的「厨房」能对上 id。

---

## 5. 采集页

**做：**

- 选图分行、每行输入框、本行按住语音 → 转写进框、可手改、可删行。
- 「开始识别」：过滤空字行，调用 `extract`，进预览或报错。
- 识别中按行数显示等待，不可重复点。

**过：** 两张图两段话能出两张草稿卡片；纯图行被跳过；全空不能识别。

---

## 6. 预览与放弃

**做：**

- 卡片展示方案中的字段（名称、数量单位、地点、日期、将新建位置、错误）。
- 「放弃录入」勾选与底栏文案切换（n 个 / 放弃本次）。
- 名称为空或 `error` 非空的卡片默认视为不可录入（或强制放弃），防止脏写。

**过：** 验收.md 中预览相关条目。

---

## 7. 保存入账

**做：**

- 未放弃项：`createLocation`（如需）→ `item.create` `source:'agent'` → 上传 → `attachMedia`。
- 逐个；失败策略按方案 §7。
- 成功后 `navigateBack` 首页，依赖现有写作废看到新条目。
- 全放弃：不调用写接口。

**过：** 家庭消息出现 agent 来源的 create 活动（现有旁路）；首页数量增加；放弃行无 item、无存储文件。

---

## 8. 解散清理

**做：**

- `family` 云函数解散分支：`removeInBatches` `familyAiKeys`、`itemMedia`，存储文件 best-effort 删除。
- 普通 leave 不删 key。

**过：** 解散后集合中无该 `familyId` 密钥；其它家庭的 key 仍在。

这是白名单里对现有 `family` 的唯一逻辑增量。

---

## 9. 收尾

- `collections.md` 与安全规则与控制台一致。
- 开发用 key 不进 git。
- 对照 [验收.md](./验收.md) 全表。
- OpenSpec tasks 勾完后再谈 archive。
