# 家庭容量会员 — 技术方案

## 1. 结论表

| 项 | 约定 |
|----|------|
| 支付 | 无微信内购；运营侧发兑换码（内测）；小程序内只兑换 |
| 权益主体 | **家庭**（`familyId`），非个人；多家庭额度见 §2.4 |
| 本刀卖点 | **容量档**：免费有硬上限，加强版家/人/物不限 |
| 免费上限 | **`familyLimit=1` / `memberLimit=2` / `itemLimit=50` / `activityLimit=30`** |
| 加强版 | `capacity_std`：家/人/物三项 `null`（不限）；**`activityLimit=200`** |
| 谁能用 | 该家任意成员，在 `expiresAt` 内按会员限额 |
| AI | BYOK 照旧；**不**因会员开关 AI；本刀不对 `extract`/`act` 做订阅硬闸 |
| 闸门 | `item.create` / `createMany`；`family.create` / `join`（家数 + 人数）；消息写入后按 `activityLimit` 截断 |
| 换绑 | 第一版不做 |
| 站内文案 | 「家庭加强版 · 内测兑换」；**不出现**闲鱼/购买引导 |

## 2. 套餐与产品（配置表驱动）

集中放在云函数共享模块（`entitlements.js`，item / family / ai / activity 各持一份须一致），**禁止**散落魔法数字。

### 2.1 计划（plan）

| planId | 说明 | `familyLimit` | `memberLimit` | `itemLimit` | `activityLimit` |
|--------|------|---------------|---------------|-------------|-----------------|
| `free` | 默认；无订阅或已过期 | `1` | `2` | `50` | `30` |
| `capacity_std` | 内测加强版 | `null`（不限） | `null` | `null` | `200` |

> **调参**：只改配置表常量，不改门控形状。内测可调 free 数字；会员家/人/物保持 **`null`**；消息保留始终有限。

### 2.2 兑换产品（product）

| productId | 绑定 plan | days | 备注 |
|-----------|-----------|------|------|
| `capacity_90d` | `capacity_std` | 90 | 内测默认季卡（product 模板） |
| `capacity_365d` | `capacity_std` | 365 | 可选；发码时选用 |

发码还可传 `durationAmount` + `durationUnit`（`day`/`week`/`month`/`year`）覆盖 `days`：月=30、年=365，范围 1–3650；默认 UI 为 **3 个月**。库内仍以码上 `days` 快照为准。

续兑：`expiresAt = max(existingExpiresAt, now) + days`；`planId` 取**最近一次产品**对应 plan（同档续期即可）。

### 2.3 灵活性约定

1. **加新档**：只加 plan + product 行；门控读 `resolveLimits(planId)`。
2. **临时开恩**：`familySubscriptions.limitsOverride`（可选对象，如 `{ itemLimit: 100, memberLimit: 5 }`）优先于 plan 表；仅 admin 可写。
3. **`features`（可选预留）**：本刀门控认 `familyLimit` / `memberLimit` / `itemLimit`；消息保留认 `activityLimit`。
4. **`source`**：`redeem` | `manual` | `wechat_pay`（预留）；逻辑不依赖 source，仅审计。
5. **过期回落**：`expiresAt < now` → 视为 `free`；**不删订阅文档**。已超额物资 / 已超员 / 已超家数：**不强制删除或踢人**；仅拦截新建物资、新加人、再建/再加第二家。

### 2.4 多家庭额度怎么判（`familyLimit`）

`familyLimit` 约束的是 **openid 的 membership 条数**，不是「当前家」的字段。

| 场景 | 规则 |
|------|------|
| 用户任一已加入家庭有**有效** `capacity_std`（解析后 `familyLimit == null`） | 再建家 / 再加入其它家：**不限** |
| 否则 | 按 `free.familyLimit=1`：已有 ≥1 条 membership 则拒绝再 create / join |
| 过期后已有 >1 家 | **不踢出**；仅拦截新增 membership |

`memberLimit` / `itemLimit` 始终读**目标家庭**的订阅（join 看被加入家；create 物资看当前家）。

## 3. 生命周期

| 事件 | 行为 |
|------|------|
| 无订阅 | 按 `free` 限额 |
| 兑换 | 须已加入家庭；码绑 `currentFamilyId`；写入/更新 `familySubscriptions` |
| 切换家庭 | 权益留在原家 |
| 离开 | 个人带不走；若离开后无任一家有效加强版，再建第二家会被拦 |
| 解散 | 删该家 `familySubscriptions`；码保留审计不回收 |
| 一码 | `unused` → `used`；可 `revoked` |
| 一家 | `_id = familyId` 一条订阅 |

## 4. 数据模型

### 4.1 `redeemCodes`

| 字段 | 说明 |
|------|------|
| `_id` | `codeHash`（规范化明文的 SHA-256 hex） |
| `product` | 如 `capacity_90d` |
| `days` | 冗余自产品表，发码时快照 |
| `planId` | 冗余快照，便于审计 |
| `status` | `unused` \| `used` \| `revoked` |
| `usedByFamilyId` / `usedByOpenid` / `usedAt` | 核销时写 |
| `createdAt` / `note` | 发码 |

明文只在 `issueCodes` 返回一次。

### 4.2 `familySubscriptions`

| 字段 | 说明 |
|------|------|
| `_id` | `familyId` |
| `familyId` | 同 `_id` |
| `planId` | 当前生效计划（未过期时） |
| `product` | 最近一次产品 id |
| `source` | `redeem` / `manual` / … |
| `expiresAt` | ms |
| `limitsOverride` | 可选；覆盖 plan 表单项 |
| `lastRedeemCodeId` | 最近码 `_id` |
| `createdAt` / `updatedAt` | |

客户端写 deny。

### 4.3 `families` 上的热路径字段（降查询成本）

| 字段 | 说明 |
|------|------|
| `itemCount` | 该家物资数量；`item.create` / `createMany` / `remove` 维持 |
| `memberCount` | 已有；join / leave / dissolve 维持；门控人数用它 |
| `entitlement` | **可选冗余快照**：`{ planId, expiresAt, itemLimit, memberLimit, familyLimit, activityLimit }`，兑换/续期时刷新 |

**真相源**：限额与到期以 `familySubscriptions` + 配置表为准。  
**`families.entitlement`**：给 `getMyFamily` / 家庭页展示用。门控写路径优先读 `familySubscriptions`。

`itemCount` 与真实集合不一致时：懒 `count()` 校准或 admin `repairItemCount`。

索引与安全规则见 `collections.md`。

## 5. 云函数 API

| 归属 | action | 说明 |
|------|--------|------|
| `family` | `getEntitlement` | 当前家：`{ planId, active, expiresAt, itemLimit, memberLimit, familyLimit, activityLimit, itemCount, memberCount, remaining* }` |
| 同上 | `redeem` / `issueCodes` | 同既有；`issueCodes` 可传 `durationAmount`+`durationUnit` 覆盖 days |
| `item` | `create` / `createMany` | `assertItemCapacity` |
| `family` | `create` | `assertUserFamilyCapacity`（家数） |
| `family` | `join` | 先 `assertUserFamilyCapacity`，再 `assertMemberCapacity`（目标家人数） |
| `family` | 解散清理 | 删 `familySubscriptions` |

核销防双兑：条件更新 `status: unused` → `used`，`stats.updated === 0` 则拒绝。

错误码：

| code | 场景 |
|------|------|
| `ITEM_LIMIT_REACHED` | 物资撞上限 |
| `MEMBER_LIMIT_REACHED` | 目标家人数撞上限 |
| `FAMILY_LIMIT_REACHED` | 该用户可加入的家庭数撞上限 |
| `INVALID_CODE` / `CODE_USED` / `CODE_REVOKED` | 兑换失败 |
| `NOT_IN_FAMILY` | 无当前家庭 |
| `FORBIDDEN` | 非 admin 发码 |
| `INVALID_DURATION` | 发码时长非法或越界 |

## 6. 门控与「查会员」成本（重点）

### 6.1 原则

> 会员检查的额外读写，必须远小于它拦下的「无限增长」读写。  
> **禁止**在 `item.list` / `search` / 首页聚合等读路径查订阅。

### 6.2 热路径开销

| 闸门 | 预算 |
|------|------|
| `item.create` | +1 订阅读（可与 family 上下文合并）+ `itemCount` 比较 |
| `family.join`（人数） | 目标家 +1 订阅读；比 `memberCount`（家文档已有则 +0） |
| `family.create` / `join`（家数） | 数该 openid 的 membership（已有 list 则复用）；若已 ≥ free 上限，再查是否存在任一家有效加强版（memberships → 对应订阅，内测可接受少量读；可后续缓存） |

**不要**：每次 create 对 `items` 做 `count()`（除非校准）。

### 6.3 `createMany`

按本批 `docs.length` 一次性校验；超剩余整批失败。

### 6.4 UI 展示成本

| 场景 | 策略 |
|------|------|
| 家庭页「加强版」行 | `getMyFamily` 的 `entitlement` + `itemCount` / `memberCount`；零额外请求 |
| 兑换成功 | 响应带新快照；作废读缓存 |
| 撞限文案 | 引导家庭页内测兑换；**不提购买渠道** |

### 6.5 校准与修复

- `item.remove` / 解散必须维护 `itemCount`（不得减到负）。
- `memberCount` 继续由 join / leave / dissolve 维护。
- `itemCount` 缺失时懒校准一次。

### 6.6 明确不做的假动作

- 不在每条活动写入前查会员  
- 不用定时全表扫算限额  
- 不为会员单独加高频轮询  

## 7. UI

- 家庭页：加强版状态、到期日、`itemCount / itemLimit`、可选展示 `memberCount / memberLimit`（不限则「不限」）。
- 兑换：`PromptDialog`；成功 Toast 到期日。
- 撞限 Toast（示例）：物资 / 人数 / 家庭数分别提示已达免费上限，可到家庭页兑换——**不提购买渠道**。
- AI 录入建物资：与手工同一 `ITEM_LIMIT_REACHED`。

## 8. 运营

1. 云函数环境变量 `ADMIN_OPENID`。
2. `issueCodes` 批量生成，线下发给内测用户。
3. 站外若收款，不写进产品文案与小程序路径。

## 9. 明确不做（本刀）

- 微信虚拟支付 / 订单表 / 自动续费  
- 个人席位、换绑  
- AI 订阅硬闸、免费 AI 日额度  
- 空间数 / 标签数 / 主题 / 图片容量门控  
- 过期强制删物资、踢人、usageLogs、成本熔断仪表盘  

## 10. 与旧 AI 兑换草案的复用

可复用：`redeemCodes` 哈希与防双兑、`familySubscriptions` 一家一条、续期公式、`issueCodes` admin、解散清理。  
需改：plan 含三项 limit；闸门含 `family.create` / `join`；文案与家庭页指标；`entitlement` 快照扩字段。
