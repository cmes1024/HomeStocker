## 2. 端到端场景（本地 API）

脚本：`server/scripts/invite-e2e.sh`（对 `http://127.0.0.1:18088` 发请求，用不同 mock openid 扮演 A / B）。

| 场景 | 步骤 | 期望 |
|------|------|------|
| E2E-1 新用户无家庭 | 用全新 openid 调 `createInviteLink` | `NO_FAMILY`，不生成链接 |
| E2E-2 正常闭环 | A 建家 → `createInviteLink` → B1 带 token 建家 → `claimInvite` | `granted`，A 家 `expiresAt` 增加 7 天，`source=invite` |
| E2E-3 一链多人 | 同一 token 让 B2、B3 各自建家并 claim | 均 `granted`，`grantedCount=3`，到期日叠加 21 天 |
| E2E-4 同一新人重复 | B1 再次建家 / 再次 claim | 不再产生奖励（`invitee_openid` 唯一） |
| E2E-5 老用户不计 | A 自己（或已建家的用户）再建家带 token | 不产生 pending，`none` |
| E2E-6 自邀 | B 用 A 的 openid 走完整链路 | `SELF_INVITE` |
| E2E-7 A 离开后 | A `leave`（非户主场景另起家庭）→ B4 带旧 token 建家并 claim | `skipped`（`INVITER_LEFT` / `FAMILY_GONE`），**B4 建家仍成功** |
| E2E-8 发奖异常不崩 | 制造奖励落点已删除后触发 claim | 返回 `skipped`，B 的家庭与 membership 完整 |
| E2E-9 重新生成 | A 重新建家 → `createInviteLink` | 新 token 生效、旧链接 inactive、累计计数不重置 |
| E2E-10 上限 | 连续 6 个新人激活 | 第 6 次 `ACTIVATION_LIMIT`，累计天数封顶 30 |
| E2E-11 原邀请链路回归 | `inviteCode` → `family.join` | 行为不变，且该 join 用户被标记为老用户 |
