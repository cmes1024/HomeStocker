> 版本：v1.1 | 日期：2026-08-11 | 状态：**愿景/早期架构，不是当前实施范围**

## 1. 技术选型

### 1.1 总览

| 层级 | 技术方案 | 说明 |
|------|----------|------|
| 前端框架 | 微信小程序原生（WXML + WXSS + JS） | 轻量、无第三方框架依赖、包体积可控 |
| 组件库 | 自研组件 + WeUI 扩展 | 基于既有 `miniprogram/components` 扩展 |
| 后端服务 | 微信云开发（CloudBase） | 免运维、自动扩缩容、与小程序深度集成 |
| 云函数 | Node.js 18（云开发运行时） | 业务逻辑、AI 接口代理 |
| 数据库 | 云开发文档数据库 + Elasticsearch（可选迁移） | 主存储用文档 DB，全文搜索用 ES 优化 |
| 对象存储 | 云开发存储（COS） | 商品图片、OCR 原图存储 |
| AI 能力 | 微信 OCR API + 云函数调用大模型 | 商品识别、语音解析 |

### 1.2 技术选型依据

**为什么选原生而非跨端框架（Taro / uni-app）：**
- 包体积更小，启动更快（目标首屏 < 2s）
- 避免框架层 bug 和版本兼容问题
- 团队微信生态经验充足，无需跨端需求

**为什么选云开发：**
- 无需独立后端部署，降低运维成本
- 天然支持微信登录鉴权
- 云函数直接调用微信 API（订阅消息、OCR 等），无需额外鉴权
- 按量付费，初期成本极低

## 3. 数据库设计

### 3.1 问题分析：文档数据库搜索慢

云开发默认的文档数据库（类 MongoDB）在以下场景存在性能瓶颈：
- **模糊搜索**：原生不支持全文索引，`regex` 查询无法利用索引，数据量增大后严重变慢
- **多字段排序**：复合排序（如按到期时间 + 名称）在无复合索引时性能差
- **聚合统计**：跨分类、跨位置的统计查询需要多次查询或复杂聚合管道

### 3.2 优化方案

**方案 A：Elasticsearch 增强搜索（推荐 V1.1 引入）**

```
文档 DB（主存储）               Elasticsearch（搜索索引）
┌─────────────────┐           ┌──────────────────────┐
│ items 集合       │ ──同步──▶ │ 物资名称（ik 分词）    │
│ families 集合    │  触发器   │ 分类 / 位置（精确匹配） │
│ users 集合       │           │ 过期时间（范围查询）    │
└─────────────────┘           └──────────────────────┘
```

- 通过云函数触发器监听文档 DB 变更，实时同步到 ES
- ES 部署在云服务器或使用腾讯云 ES 服务
- 搜索请求通过云函数代理转发到 ES

**方案 B：轻量级过渡方案（V1.0 MVP 适用）**

在 ES 就绪前，通过以下手段缓解搜索性能问题：
- 客户端本地缓存全量物资数据（单家庭物资量有限，通常 < 500 条）
- 前端做内存搜索和排序，秒级响应
- 数据库仅做精确查询和分页拉取
- 建立复合索引：`{ familyId: 1, category: 1 }`、`{ familyId: 1, expireDate: 1 }`、`{ familyId: 1, location: 1 }`

## 4. 云函数设计

### 4.1 函数清单

| 云函数 | 功能 | 调用频率 | 说明 |
|--------|------|----------|------|
| `familyManage` | 家庭 CRUD、成员管理 | 低 | 创建/加入/退出/设置 |
| `itemManage` | 物资 CRUD | 高 | 核心业务，需优化冷启动 |
| `itemSearch` | 物资搜索 | 高 | 未来代理到 ES |
| `ocrRecognize` | OCR 识别 + AI 解析 | 中 | 调用微信 OCR + 大模型 |
| `notification` | 定时发送到期提醒 | 低（定时） | 定时触发器，每日执行 |
| `shoppingList` | 采购清单管理 | 中 | 清单 CRUD |
| `userProfile` | 用户信息管理 | 低 | 登录初始化、设置 |

### 4.2 itemManage 云函数示例结构

```javascript
// cloudfunctions/itemManage/index.js
exports.main = async (event, context) => {
  const { action, data, familyId } = event;
  const { OPENID } = cloud.getWXContext();

  // 1. 权限校验：用户是否属于该家庭
  await checkFamilyMember(OPENID, familyId);

  // 2. 角色权限校验（删除操作需 Owner/Admin）
  await checkRolePermission(OPENID, familyId, action);

  // 3. 路由到具体 handler
  switch (action) {
    case 'add':    return addItem(data, familyId, OPENID);
    case 'update': return updateItem(data, familyId, OPENID);
    case 'delete': return softDeleteItem(data.itemId);
    case 'list':   return listItems(data, familyId);
    case 'detail': return getItemDetail(data.itemId);
    default: throw new Error('Unknown action');
  }
};
```

### 4.3 定时触发器：到期提醒

> 现状（Java 后端）：`server` 的 `ExpireNotifyJob` 每分钟扫描，按各家庭配置的 `expireReminderHour` / `expireReminderMinute` 命中发送时间；候选物资取 `expireDate` 恰好等于「今天 + 家庭配置的提前天数」的那批。下列云函数方案为历史参考。

```javascript
// cloudfunctions/notification/config.json（历史）
{
  "triggers": [{
    "name": "dailyExpireCheck",
    "type": "timer",
    "config": "0 0 9 * * * *"  // 历史：每天 9:00 执行
  }]
}
```

逻辑流程：
1. 查询所有 `expireReminderEnabled: true` 的家庭
2. 在这些家庭中查询 `expireReminderEnabled: true` 且 `expireDate` 在「今天 + 该家庭配置的提前天数」到期的物资
3. 按家庭分组，聚合提醒内容
4. 通过 `cloud.openapi.subscribeMessage.send()` 向家庭成员推送（现由 Java `WeChatClient.sendSubscribeMessage` 实现）

## 5. AI 录入技术方案

### 5.1 流程

```
用户拍照/选择照片
    │
    ▼
调用微信原生 OCR API（wx.chooseMedia + 云函数代理）
    │
    ▼
云函数 OCR 识别 → 返回原始文本
    │
    ▼
云函数调用 AI 大模型 → 结构化解析（名称、数量、保质期等字段）
    │
    ▼
返回给小程序前端 → 预填充表单 → 用户确认/修改 → 提交保存
```

### 5.2 OCR 方案

- **条形码识别**：使用微信 `wx.scanCode` API 直接获取商品条码，再通过第三方商品库查询
- **小票/包装识别**：使用微信云开发的 OCR 云调用能力（`cloud.openapi.ocr.printedText`）
- **语音录入**：使用微信 `wx.startRecord` + 云函数语音识别 API，再通过大模型解析

### 5.3 AI 解析 Prompt 设计

```
你是一个物资管理助手。请从以下 OCR 识别结果中提取结构化信息，
返回 JSON 格式：

输入文本："{ocrResult}"

解析规则：
- name: 商品名称
- category: 分类（食品饮料/生鲜果蔬/调味品/药品保健/日用品/母婴用品/宠物用品/其他）
- quantity: 数量（数字）
- unit: 单位（个/瓶/袋/kg/g/箱/盒/包）
- expireDate: 保质期到期日（YYYY-MM-DD），如无则 null
- notes: 其他备注信息

只返回 JSON，不要其他内容。
```

## 7. 缓存与离线策略

### 7.1 缓存层级

| 缓存类型 | 存储方式 | TTL | 内容 |
|----------|----------|-----|------|
| 内存缓存 | `getApp().globalData` | 会话级 | 当前家庭信息、用户角色 |
| 本地存储 | `wx.setStorageSync` | 30 分钟 | 物资列表、分类/位置配置 |
| CDN 缓存 | 云存储 CDN | 永久 | 物资图片、头像 |

### 7.2 离线模式

- 首次加载后缓存物资列表到本地
- 离线时展示缓存数据并标记"离线模式"
- 网络恢复后自动同步变更
- 离线期间的操作入队，恢复后逐一提交（暂不支持冲突合并，以后到为准）

## 8. 安全设计

- **鉴权**：依赖云开发天然的用户身份（`wxContext.OPENID`），无需自建登录
- **数据隔离**：所有查询强制带 `familyId` 过滤，云函数中校验成员身份
- **注入防护**：使用云开发 SDK 的参数化查询，避免注入
- **敏感操作**：解散家庭、移除成员等操作需云函数二次校验 + 前端二次确认
- **频率限制**：云函数配置并发限制，防止恶意请求
