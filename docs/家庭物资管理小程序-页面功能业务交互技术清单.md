# 家庭物资管理小程序页面功能业务交互技术清单

> 整理依据：`PRD-家庭物资管理小程序.md`、`家庭物资管理小程序-功能清单.md`、`微信小程序新能力研究与设计约束.md`、当前原型 `family-supplies-prototype`
>
> 文档目的：按页面梳理每个功能点对应的**业务目标、交互方式、前端使用技术/实现建议**，用于同步产品、设计、前端研发。
>
> 适用对象：产品经理、交互设计师、视觉设计师、前端开发。

## 1. 文档说明

本文档按“页面”而不是按“模块”整理，方便直接映射到原型和前端页面文件。

每个页面会从 4 个维度展开：

1. 页面业务定位：这个页面在整个产品链路里的价值
2. 功能点清单：页面上承载的主要能力
3. 交互说明：用户如何进入、操作、返回、关闭
4. 前端技术建议：建议使用的小程序页面模型、组件、交互能力、渲染能力

为了避免遗漏，文档最后还单独补了：

1. 跨页面公共能力
2. 尚未展开为独立页面/面板，但 PRD 已定义的能力

## 2. 全局页面技术基线

在逐页展开前，先统一当前项目后续的前端设计与实现基线。

### 2.1 页面模型基线

1. 核心页面优先采用 `Skyline`
2. 顶部导航统一采用**自定义导航**
3. 页面滚动统一优先采用**局部滚动**，主内容区使用 `scroll-view`
4. 弹层、选择器、半屏管理态优先采用 `page-container` 或 `自定义路由`
5. 高价值转场优先考虑 `共享元素`
6. 跟手、拖拽、滑动关闭优先考虑 `worklet + 手势系统`

### 2.2 页面范围

当前原型已存在 6 个主页面：

1. 引导页 `onboarding.html`
2. 首页 `home.html`
3. 物资列表页 `inventory.html`
4. 添加物资页 `add-item.html`
5. 物资详情页 `item-detail.html`
6. 家庭页 `family.html`

### 2.3 建议的页面渲染策略

| 页面 | 建议渲染 | 原因 |
|------|------|------|
| 引导页 | `Skyline` 或全局统一配置 | 首次体验页，结构简单，可跟随全局 |
| 首页 | `Skyline` | 高频入口，信息密度高，需更流畅滚动和切页 |
| 物资列表页 | `Skyline` | 长列表、高频浏览、筛选与详情跳转 |
| 添加物资页 | `Skyline` | 涉及录入、识别、表单、面板 |
| 物资详情页 | `Skyline` | 适合做共享元素、跟手微交互 |
| 家庭页 | `Skyline` | 多家庭切换、半屏管理、手势关闭很适合增强能力 |

## 4. 引导页

### 4.1 页面业务定位

引导页用于承接**首次打开且未创建/未加入家庭**的用户，帮助用户尽快理解产品价值，并完成首次家庭建立或加入。

### 4.2 主要功能点

| 功能点 | 业务说明 | 交互说明 | 前端使用技术/建议 | 当前情况 |
|------|------|------|------|------|
| 首次进入展示 | 仅对没有家庭的用户展示 | 命中条件后进入；已存在家庭则直接进首页 | 页面进入逻辑由页面路由守卫/启动逻辑控制；不依赖页面内判断文案 | 已在 PRD 和原型体现 |
| 创建家庭入口 | 新用户创建第一个家庭 | 点击“创建家庭”进入创建流程，完成后跳首页 | 页面按钮事件；后续建议接半屏创建页或独立创建页 | 已体现 |
| 加入家庭入口 | 新用户通过邀请码加入已有家庭 | 点击“加入家庭”进入输入邀请码流程 | 页面按钮事件；后续可接半屏输入面板或独立页 | 已体现 |
| 创建/加入后进入首页 | 完成家庭建立后进入默认家庭首页 | 成功后跳转首页，不回到引导页 | 页面跳转；后续建议关键路径预加载首页 Skyline 环境 | 已体现 |
| 产品价值说明 | 传达避免重复采购、临期提醒、家庭协同 | 通过价值卡片帮助用户快速理解 | 静态信息模块；可继续保持轻量，不建议过多动画 | 已体现 |
| 授权与隐私说明 | 告知昵称头像用途及协议说明 | 用户阅读后进入后续流程 | 自定义内容模块；授权链路遵循微信官方能力 | 已体现 |
| 不再重复展示说明 | 明确这是一次性引导 | 创建/加入后，下次直接进入首页 | 文案说明 + 启动逻辑控制 | 已体现 |

### 4.3 页面交互重点

1. 进入条件必须是“首次 + 无家庭”
2. 创建/加入家庭后，直接进入首页，不提供“先看看首页”这类绕路入口
3. 引导页应保持轻量，不宜做复杂滚动和层叠弹层

### 4.4 前端技术建议

1. 页面结构可保持简单静态布局
2. 若项目全局按 `Skyline` 设计，可直接纳入 Skyline 页面体系
3. 使用自定义导航而非依赖原生导航
4. 不需要复杂 `worklet` 动画，重点在进入逻辑和路由正确性
5. 后续如果加入创建家庭的半屏流程，可使用 `page-container` 或半屏路由

## 5. 首页

### 5.1 页面业务定位

首页是整个小程序的**核心总览页**，负责展示当前家庭状态、提醒总览、快捷入口、临期预览和最近操作，是最高频页面之一。

### 5.2 主要功能点

| 功能点 | 业务说明 | 交互说明 | 前端使用技术/建议 | 当前情况 |
|------|------|------|------|------|
| 当前家庭展示 | 让用户明确当前所在家庭 | 首屏看到当前家庭名称与状态 | 自定义导航/顶部壳层固定展示 | 已体现 |
| 家庭切换主入口 | 首页顶部作为多家庭主入口 | 点击进入切换/管理家庭 | 建议后续用 `page-container` 或半屏自定义路由承接，不一定必须整页跳转 | 已体现 |
| 家庭成员/提醒总开关摘要 | 首页快速看到家庭协作状态 | 作为家庭状态摘要展示 | 静态摘要卡片 | 已体现 |
| 多家庭快捷切换提示 | 告知多家庭管理能力 | 通过胶囊组展示已有家庭 | 可作为半屏切换面板的入口反馈区 | 已体现 |
| 今日提醒总览 | 临期、过期、待补货等总览 | 点击可进入详细列表或详情 | 信息卡片 + 详情跳转 | 已体现 |
| 临期详情入口 | 进入临期相关物资处理链路 | 点击提醒卡进入列表/详情 | 普通跳转；后续建议配合 `wx.preloadSkylineView` | 已体现 |
| 快捷入口：添加物资 | 进入物资录入 | 点击进入添加物资页 | 普通页面跳转 | 已体现 |
| 快捷入口：拍照录入 | 进入 OCR 录入链路 | 点击进入添加物资页中的识别流程 | 普通页面跳转 | 已体现 |
| 快捷入口：查看全部物资 | 快速进入列表管理 | 点击进入物资列表页 | 普通页面跳转 | 已体现 |
| 临期物资预览 | 快速查看高优先级物资 | 点击单项可进详情 | 卡片式列表；后续可加共享元素 | 已体现 |
| 最近操作 | 展示家庭成员最近动作，增强协作感知 | 浏览即可，必要时可跳详情 | 信息流模块 | 已体现 |
| 待补货信息 | 首页预警库存不足物资 | 作为提醒总览一部分展示 | 信息卡片 + 后续采购链路入口 | 已体现 |
| 采购日提示 | 为家庭采购提供节奏提示 | 信息展示为主 | 可继续保留为静态模块 | 已体现 |

### 5.3 页面交互重点

1. 首页应是“固定顶部 + 内容滚动区 + 固定底部导航”
2. 家庭切换入口建议固定在顶部壳层，不随内容滚动
3. 从首页进入列表、详情、家庭管理前，适合做关键页预加载
4. 首页所有卡片点击应保持反馈统一、节奏轻快

### 5.4 前端技术建议

1. 建议采用 `Skyline`
2. 内容区使用 `scroll-view`
3. 顶部使用自定义导航/固定头部
4. 后续若首页信息继续增多，可引入 `sticky-header`
5. 从首页进入高频页面前，可使用 `wx.preloadSkylineView`
6. 家庭切换建议后续采用 `page-container` 或 `自定义路由`
7. 卡片按压、面板弹起、下滑关闭等后续增强交互可由 `worklet` 承担

## 6. 物资列表页

### 6.1 页面业务定位

物资列表页是用户管理家庭库存的核心工作页，承担浏览、搜索、筛选、查看详情、进入新增等动作。

### 6.2 主要功能点

| 功能点 | 业务说明 | 交互说明 | 前端使用技术/建议 | 当前情况 |
|------|------|------|------|------|
| 页面标题与当前模块识别 | 明确当前处于物资管理场景 | 通过自定义顶部标题展示 | 自定义导航 | 已体现 |
| 搜索入口 | 按名称/分类/位置搜索物资 | 点击输入框输入关键词筛选 | 建议搜索区放在固定头部或列表顶部 | 原型已体现入口，功能待深化 |
| 新增物资入口 | 从列表快速进入新增页 | 点击按钮进入添加物资页 | 普通跳转 | 已体现 |
| 筛选：分类 | 按分类筛选 | 点击后选择分类条件 | 后续建议半屏筛选面板或吸顶筛选条 | 已体现语义 |
| 筛选：位置 | 按存放位置筛选 | 点击后选择位置 | 同上 | 已体现语义 |
| 排序：临期优先 | 提高高风险物资处理效率 | 点击后切换排序规则 | 筛选/排序区统一管理 | 已体现语义 |
| 视图模式：卡片 | 适合快速扫读状态 | 点击后切换到卡片模式 | 卡片模式适合移动端默认态 | 已体现 |
| 视图模式：表格 | 适合高效率管理 | 点击切换为紧凑表格模式 | 仍建议基于小程序布局能力实现，不按 Web table 思路硬做 | 原型有提示，未展开 |
| 物资清单浏览 | 浏览所有物资 | 上下滚动查看列表项 | 长列表结构必须为 Skyline 友好结构 | 已体现 |
| 列表项摘要 | 展示名称、位置、库存、分类、状态 | 点击卡片进入详情 | 列表卡片应保持结构统一 | 已体现 |
| 临期状态标签 | 突出优先处理项 | 标签点击可不单独交互，整体点击卡片 | 建议与详情共享元素联动 | 已体现 |
| 库存关注标签 | 提示低库存或关注状态 | 随列表项一起展示 | 统一状态标签体系 | 已体现 |
| 列表统计摘要 | 展示总件数、临期数、低库存数 | 列表底部/顶部展示 | 可作为统计摘要卡 | 已体现 |
| 进入物资详情 | 进入单个物资详情页 | 点击卡片跳转详情 | 推荐后续加 `共享元素` | 已体现 |

### 6.3 页面交互重点

1. 列表应优先服务“快速扫读”和“快速定位”
2. 筛选和排序应尽量固定在列表顶部区域，而不是散在页面中部
3. 卡片进入详情建议做连续过渡，不要只是硬切页
4. 表格模式是效率功能，但不能破坏移动端可读性

### 6.4 前端技术建议

1. 强烈建议采用 `Skyline`
2. 列表主体使用 `scroll-view type="list"`
3. 列表项建议使用 `list-item`
4. 若后续加入分组吸顶，优先考虑 `sticky-header` / `list-view`
5. 列表进入详情建议用 `share-element`
6. 不建议用一层大容器把所有卡片包起来，否则会削弱长列表按需渲染价值
7. 表格模式建议仍基于 flex / block 思路适配小程序，不按浏览器 table 强依赖实现

## 7. 添加物资页

### 7.1 页面业务定位

添加物资页承担“从识别到确认再到保存”的录入链路，是产品降低录入门槛的关键页面。

### 7.2 主要功能点

| 功能点 | 业务说明 | 交互说明 | 前端使用技术/建议 | 当前情况 |
|------|------|------|------|------|
| 返回物资列表 | 回到列表，不打断主流程 | 点击返回按钮回列表 | 自定义导航返回 | 已体现 |
| 拍照识别入口 | 优先通过 OCR 识别包装信息 | 点击进入拍照识别 | 识别能力入口；后续结果确认建议半屏承接 | 已体现 |
| 扫码录入入口 | 快速录入标准包装商品 | 点击进入扫码链路 | 独立识别入口 | 已体现 |
| 语音补充 | 降低补充说明的录入成本 | 点击后语音输入说明 | 语音补充入口；结果回填表单 | 已体现 |
| AI 预填状态 | 告知系统等待或完成识别 | 用户拍照/扫码后自动回填 | 识别状态模块 | 已体现 |
| 基础信息：名称 | 核心物资识别字段 | 用户检查并可修改 | 表单字段 | 已体现 |
| 基础信息：分类 | 决定列表展示与统计归类 | 用户选择分类 | 建议后续做为半屏选择器而非普通下拉 | 已体现 |
| 基础信息：数量 | 记录当前库存基数 | 用户输入或调整数量 | 表单字段 | 已体现 |
| 基础信息：位置 | 决定后续查找与位置视图 | 用户选择存放位置 | 建议后续做为半屏选择器 | 已体现 |
| 到期与提醒设置 | 决定是否启用提醒 | 用户填写保质期并开关提醒 | 表单 + 开关组件 | 已体现 |
| 提醒节奏说明 | 告知提前提醒逻辑 | 用户浏览建议文案 | 说明模块 | 已体现 |
| 备注输入 | 补充采购来源、适用对象、使用建议 | 多行输入 | 表单字段 | 已体现 |
| 保存前确认 | 确认名称、数量、位置已填完整 | 保存前给出状态反馈 | 表单校验提示 | 已体现 |
| 保存物资 | 完成新增 | 点击保存后回列表或详情 | 主 CTA | 已体现 |

### 7.3 页面交互重点

1. 录入流程应是“识别优先，人工确认补充”
2. 分类、位置、提醒策略等选择类动作，不建议用网页式下拉菜单
3. 保存按钮应始终明确当前是否可提交
4. OCR / 扫码 / 语音只是录入方式，不应让页面变成多个复杂浮层叠加

### 7.4 前端技术建议

1. 建议采用 `Skyline`
2. 表单主体使用局部滚动结构
3. 分类、位置、提醒规则等选择型交互，建议后续采用 `page-container`
4. 若需要“从底部弹起的确认页 / 识别结果页”，可采用 `自定义路由`
5. 面板下滑关闭、跟手回弹等细节，适合用 `worklet`
6. 页面结构要严格按微信小程序的表单页逻辑设计，不要做浏览器式复杂弹窗群

| 最近操作记录 | 追踪谁改了什么 | 查看最近调整历史 | 信息流模块 | 已体现 |
| 编辑信息 | 进入编辑物资页 | 点击进入编辑流程 | 普通跳转或复用添加页编辑态 | 已体现 |
| 删除物资 | 删除当前物资 | 点击后应二次确认 | 敏感操作，需确认机制 | 已体现入口，确认流程待补 |

### 8.3 页面交互重点

1. 详情页不是纯展示页，而是“查看 + 快调 + 管理”
2. 库存加减应足够快，但又不能让用户误操作无感知
3. 删除等敏感动作必须补齐确认链路
4. 列表进入详情应尽量有连续感

### 8.4 前端技术建议

1. 建议采用 `Skyline`
2. 列表卡片进入详情建议使用 `share-element`
3. 库存加减按钮按下反馈、状态更新动画适合 `worklet`
4. 后续如果有图片预览、备注编辑、提醒策略设置，可采用 `page-container` 或半屏路由
5. 详情页同样应采用自定义导航和局部滚动结构

## 9. 家庭页

### 9.1 页面业务定位

家庭页承担多家庭管理、家庭成员管理、家庭提醒总开关、位置与分类管理，是“家庭维度后台”的核心页面。

### 9.2 主要功能点

| 功能点 | 业务说明 | 交互说明 | 前端使用技术/建议 | 当前情况 |
|------|------|------|------|------|
| 当前家庭总览 | 展示当前家庭名称、成员规模、邀请码、提醒状态 | 首屏查看 | 顶部信息卡 | 已体现 |
| 家庭邀请码 | 支持邀请成员加入 | 点击复制邀请码 | 信息展示 + 复制行为 | 已体现 |
| 家庭列表管理 | 查看全部家庭并管理切换、新增、编辑、删除 | 中心管理区域 | 推荐后续做半屏切换/管理态 | 已体现 |
| 创建家庭 | 新增新的家庭空间 | 点击创建进入创建流程 | 后续建议半屏创建页 | 已体现 |
| 编辑当前家庭 | 修改当前家庭基础信息 | 点击“编辑信息”进入编辑 | 后续建议半屏编辑页 | 已体现 |
| 切换到其它家庭 | 切换当前家庭上下文 | 点击“切换到这里”后刷新全局状态 | 切换后首页、列表、提醒都应同步刷新 | 已体现 |
| 编辑其它家庭 | 管理非当前家庭信息 | 点击进入编辑 | 半屏或独立页均可 | 已体现 |
| 删除家庭 | 删除指定家庭 | 点击后需确认 | 敏感操作，需权限与确认 | 已体现入口，确认待补 |
| 加入已有家庭 | 通过邀请码加入现有家庭 | 点击后进入输入邀请码流程 | 半屏输入面板更适合 | 已体现 |
| 家庭提醒总开关 | 控制当前家庭提醒是否启用 | 点击开关实时切换 | 开关组件 | 已体现 |
| 家庭成员查看 | 查看成员及角色 | 浏览或点查看全部 | 成员列表模块 | 已体现 |
| 邀请成员 | 发起邀请协作 | 点击进入邀请流程 | 按钮入口 | 已体现 |
| 位置管理 | 维护家庭位置体系 | 点击进入位置管理 | 后续可拆独立管理面板/页 | 已体现入口 |
| 分类管理 | 维护家庭分类体系 | 点击进入分类管理 | 后续可拆独立管理面板/页 | 已体现入口 |
| 退出家庭 | 成员退出当前家庭 | 点击后确认退出 | 敏感操作，需确认 | 已体现入口 |

### 9.3 页面交互重点

1. 家庭页不只是“设置页”，而是多家庭上下文管理中心
2. “切换家庭”与“管理家庭”应是同一个逻辑域下的两类操作
3. 删除家庭、退出家庭、邀请成员都属于高风险/高价值操作，交互要明确
4. 家庭页后续非常适合做成“主页面 + 半屏管理态”的结构

### 9.4 前端技术建议

1. 建议采用 `Skyline`
2. 主内容区使用 `scroll-view`
3. 家庭切换面板、创建/编辑家庭、邀请码输入，建议后续采用 `page-container`
4. 如果要强调更强原生感，可使用 `自定义路由` 做半屏页推进
5. 面板下滑关闭、卡片按压反馈、管理页跟手交互适合 `worklet + 手势系统`
6. 不建议把家庭管理做成大量网页式弹窗和下拉菜单

## 10. 跨页面公共能力

这一部分不是某一个页面独有，但必须纳入整体设计与实现规划，否则页面之间会割裂。

### 10.1 页面跳转与导航

| 能力 | 业务意义 | 交互说明 | 前端使用技术/建议 |
|------|------|------|------|
| 底部导航 | 首页 / 物资 / 家庭 三大主域切换 | 用户在主域间切换 | 自定义底部导航 |
| 返回逻辑 | 保持层级清晰 | 返回上一页或关闭当前容器 | 页面返回 + `page-container` 关闭逻辑 |
| 关键页预加载 | 缩短核心页面进入等待 | 从首页进入高频页更快 | `wx.preloadSkylineView` |
| 页面转场升级 | 提升近原生体验 | 列表进入详情、首页进入家庭切换 | `自定义路由`、`share-element` |

### 10.2 通用前端结构

1. 自定义导航
2. 页面固定壳层
3. 内容区局部滚动
4. 统一状态标签体系
5. 统一按钮反馈、开关、列表卡片、信息卡组件

### 10.3 通用交互细节

1. 主 CTA 要始终清晰
2. 敏感操作要二次确认
3. 切换家庭后需有明确状态反馈
4. 长列表优先保证滚动与点击的流畅性
5. 面板型交互优先支持下滑关闭
